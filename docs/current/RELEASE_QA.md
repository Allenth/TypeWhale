当前安装版为 2.0.58 (Build 919)，已通过唯一入口编译、覆盖安装、深度签名和启动。公开源码候选从既有公开 `main` 导入最终树快照，不携带 776 个本地开发提交历史、模型、运行时、安装包或未跟踪目录；个人绝对路径、常见密钥模式、GitHub 100MB 限制、许可证和第三方声明已核对。RC003 产品照片因公开再分发文书未随仓库提供而主动排除，公开源码无照片构建与 Remote 完整回归通过，缺图时映射页保持可用。本轮是源码发布，不是新的 DMG、公证或模型分发；GitHub 远端树仍须在实际推送／合并后复核才能判定公开发布完成。

“源码存在”“自动测试通过”“安装版通过”“公开分发通过”是不同证据层级。测试文件存在不等于本轮执行，脚本退出 0 不等于新 build 已安装（构建锁分支可能跳过）。

## 每次代码交付前

1. 先按 [AGENTS](../../AGENTS.md) 复述目标、范围、do-not-touch 和验收。
2. 在主目录执行 `git branch --show-current`、`git status --short`、`git diff --stat`；检查构建进程与源码、版本文件、日志 mtime。来源不明修改不得覆盖或提交；发现重叠写入先只读。
3. 读取 [构建版本字段](../../native/build_native_app.sh)。按即将生成的版本／build 更新 [应用内版本历史](../../native/Sources/Presentation/VersionHistory/VersionHistoryViewController.swift) 与 [开发日志](DEVELOPMENT_LOG.md)。版本被其他 session 改动或守卫拒绝时重新检查。
4. 按修改影响选择 [native/Tests](../../native/Tests/) 中的回归与已有执行入口，先读脚本再运行；不要假定 `.swift` 文件均可单独运行，也不要无差别跑历史实验探针。
5. 涉及交互完成设计 review，并在安装后补截图或录屏。

可用于定位回归的真实文件示例（不是统一测试命令）：[鼠标侧键](../../native/Tests/MouseShortcutExclusiveEventTapBoundaryCheck.sh)、[自动发送设置](../../native/Tests/AutoSendSettingsStoreCheck.swift)、[OpenClaw](../../native/Tests/OpenClawClientCheck.swift)、[媒体桥接](../../native/Tests/SystemMediaRemoteBridgeBoundaryCheck.sh)、[提示词边界](../../native/Tests/SmartRewriteSystemPromptBoundaryCheck.sh)。最终报告应写实际执行命令、结果与未测范围。

## 唯一构建入口

从仓库根目录执行，经并发检查后选择所需动作：

```bash
./native/build_and_log.sh
./native/build_and_log.sh --full-version
./native/build_and_log.sh --package
```

第一条为日常源码编译、build +1、短版本不变、覆盖 `/Applications/TypeWhale Pro.app`、启动与写自动日志。第二条只在完整版本更新时用；第三条同时生成分发 DMG。完整版本仅递增 patch，例如 1.2.9 → 1.2.10。

`--install-only` 仅用于明确重新安装已有包，不能作为改代码后的验证。不得恢复自动 Stop 构建 hook，也不得用底层脚本绕过统一流程。

脚本仍会使用根 README、macOS README、原 [构建日志](../构建日志.md) 路径。本轮不改脚本。**新文档入口的版本快照需要发布者同步，不会自动更新。**

## 发布放行、风险与回退

- 本地交付：核对安装包版本、签名检查、启动结果和构建日志；对相关行为完成真实回归。日志附 build、提交、命令、证据和剩余风险。
- 公开发布：另核验实际 DMG 资产、Developer ID、公证、Gatekeeper、干净机器安装、模型／运行时许可、隐私与服务条款、升级和支持方案。本轮没有宣布这些门槛已通过。
- MediaRemote 是非公开能力；当前实现不能直接作为 Mac App Store 路线已就绪的依据。
- 发布前再次 `git status --short`，仅 stage 本轮拥有的文件。代码 build 对应的版本、日志、历史与源码需一并提交；不提交他人 dirty 或含用户素材的实验产物。
- 失败时先保存诊断和用户数据，停止继续分发；定位已验证的上一构建及其来源，再决定安装回退。不要为回退执行破坏性清理或覆盖他人修改。
