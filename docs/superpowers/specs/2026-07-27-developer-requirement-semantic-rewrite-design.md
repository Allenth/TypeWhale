# 开发需求语义整理强化设计

日期：2026-07-27

## 目标

强化“开发需求”模式，让本地 Qwen3 4B 不再只做字面润色，而是先理解口述中的真实
产品或开发意图，再输出可以直接发送给 coding agent 的需求正文。

本轮只调整“开发需求”。“极致归纳”、其他整理模式、ASR、模型选择、失败处理、
粘贴和自动发送流程保持不变。

## 输出定位

输出采用直接需求正文：

- 不添加“我理解你的需求是”等前言；
- 不询问“如果理解正确是否开始”；
- 不回答或执行原文中的问题和动作；
- 不替用户扩写技术方案、原因、验收项或原文没有的限制。

## 语义整理规则

模型应在内部完成理解，不输出分析过程：

1. 判断原文是需求、反馈、问题、排查说明还是限制。
2. 识别用户明确提到的对象、希望改变的行为、操作方式、状态或位置关系，以及要求
   保留的既有逻辑。
3. 删除无意义填充词、口吃、紧邻重复和能够明确判断的自我修正。
4. 将断裂口语重组为自然、直接的需求表达，但不添加原文没有的信息。
5. 空间、时间、数量、否定和强度关系不得被弱化。例如原文只说“中心对齐”时，
   不得擅自缩窄成“水平中心对齐”；只有原文明说横向或纵向时才限定单一方向。
6. 一个意思的短句仍保持一句；存在多个明确要求时才自然分句或分行；原文明列步骤
   时才使用编号并保持顺序。
7. 无法确认的术语、主体或关系保留原话，不根据读音猜测。

## 证据驱动的口吃预清理

本地 Qwen3 4B 首轮三次回放均原样保留相邻的否定式词头重启，证明只增加文字规则仍
不足以稳定清理这一类语音噪声。开发需求模式因此增加一层窄范围、确定性的输入预清理：

- 只处理 `不 + 单个汉字 + 不 + 同一汉字` 的相邻重启，删除前一组未说完的词头；
- 只在 `.developerRequirement` 送入模型前生效，不改 ASR 原始记录；
- `不听不信` 等前后汉字不同的正常并列表达保持不变；
- 同一句中前后重复同一个双字动作、后句用“也”引出新对象时，使用句号划开并列
  要求，避免 4B 把后句对象接成前句补语；
- 不做开放式纠错，不猜测术语、主体或缺失事实。

## 末尾标点

“开发需求”最终输出的末尾不保留中文句号 `。` 或英文句点 `.`：

- 提示词明确要求末尾不加句号；
- 交付前增加仅作用于 `.developerRequirement` 的确定性清理，防止模型偶发不遵守；
- 正文内部的句号正常保留；
- 问号、感叹号、冒号、引号及其他有语义的结尾标点不删除；
- 其他整理模式不受影响。

## 默认模板迁移

现有用户可能保存了与当前默认值完全一致的旧模板。新版本必须把当前默认模板加入
已知旧默认集合，使其自动迁移到新默认；用户真正编辑过的自定义模板继续保留。

## 自动化测试

提示词契约和真实本地模型回放至少覆盖：

1. 倒计时真实口述：删除“不显不显示”等口吃，保留整条点击取消，并把“中心对齐”
   保持为完整中心关系，不擅自缩窄为仅水平。
2. 一句话短要求：保持简短，不增加标题、解释、注意事项或确认话术。
3. UI 反馈：保留用户的判断强度和要求恢复的具体对象。
4. 多步骤长需求：保留顺序、数字、时间、否定、疑问和限制。
5. 旧逻辑保留要求：不能因突出新功能而删除“继续保留”的行为。
6. 不确定术语：保留原话，不猜成已知模型或产品名。
7. 末尾标点：中文句号和英文句点被移除，问号与感叹号保留，其他模式不变。

真实回放固定使用本地 Qwen3 4B，至少运行上述六类语义样例。每轮向用户展示原始
输入、模型输出、耗时和未满足项，不能只报告“通过”。

## 验收标准

- 倒计时样例能直接表达三个要求：无独立取消按钮、整条点击取消、倒计时条与胶囊
  中心对齐。
- 不输出确认前言、结尾询问或新的技术方案。
- 简单短句不扩写，长需求不丢失明确事实和限制。
- 开发需求末尾没有 `。` 或 `.`，其他有语义的结尾标点保持。
- 本地 Qwen3 4B 多轮回放结果达到可直接使用水平，并完整展示给用户判断。
- 现有用户自定义提示词、其他模式和产品主流程不发生行为变化。
