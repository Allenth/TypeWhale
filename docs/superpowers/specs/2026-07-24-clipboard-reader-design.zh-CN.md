# TypeWhale 内容朗读功能设计规格

日期：2026-07-24
状态：已加入网页正文与 OCR 方案，等待书面规格复核
负责人：TypeWhale 产品与工程

## 一、功能概述

TypeWhale 在现有“声音”Tab 下新增正式子功能：**内容朗读**。

内容可以来自三种入口：

1. 已授权应用中的新复制文字；
2. Chrome 扩展从当前网页提取的正文；
3. 用户框选屏幕区域或窗口后，本地 OCR 识别的文字。

TypeWhale 把三类内容统一转换成 Reader Item，加入最近内容列表，生成适合朗读的文本，并在可拖动的屏幕浮动工具条中显示和播放。

默认授权来源是 Codex。用户可以自行增加其他应用。

正式交付版本必须使用原生、隔离的 TTS Helper，不允许依赖用户电脑上的 Python、`pip` 或虚拟环境。

## 二、产品目标

为有阅读困难的用户提供低操作成本、可预测的听读流程：

1. 在 Codex 点击“复制”，或者点击“朗读网页”或“OCR”；
2. 文字出现在 TypeWhale 浮动朗读工具条；
3. 用户点击播放；明确执行“朗读网页”或“OCR”时，识别成功后直接播放；
4. 用户可以暂停、继续、停止、改变音色与语速，或者选择最近的其他内容。

## 三、不在本期范围内

- 不建设第三方通用插件平台。
- 不使用云端 TTS 作为自动后备。
- 正式功能不使用 Python。
- 不读取未授权应用的复制内容。
- 不把所有复制内容自动排成连续播放队列。
- 默认不跨重启保存复制历史。
- 模型不支持情绪时，不伪装成支持情绪。
- 默认不朗读代码。
- 不修改系统剪贴板中的原始内容。
- 不绕过登录、付费墙、验证码、网站权限或其他访问控制。
- 不在后台抓取用户没有主动要求朗读的网页。
- Chrome 扩展首版不扩展为通用浏览器自动化工具。

## 四、功能入口

### 4.1 声音 Tab

在现有“声音”Tab 新增“内容朗读”分组，包含：

- 功能总开关；
- “显示朗读工具条”按钮；
- Chrome 扩展安装、连接状态与修复入口；
- 允许监听的应用列表；
- 工具条显示模式；
- 默认音色；
- 默认情绪；
- 默认语速；
- 默认音量；
- 是否朗读代码；
- 最近记录数量；
- 是否跨重启保存记录；
- 清空朗读记录；
- 模型状态与安装/修复入口。

### 4.2 菜单栏

TypeWhale 菜单栏增加“显示朗读工具条”。

即使浮窗被隐藏，用户仍可以从声音 Tab 或菜单栏重新显示。

### 4.3 浮动工具条内容入口

展开状态增加：

- “朗读网页”按钮；
- “OCR”按钮；
- OCR 模式选择：框选区域或整个窗口，默认框选区域。

“朗读网页”和“OCR”属于用户明确发起的播放操作，不受“复制后自动播放”勾选项控制。

## 五、复制来源授权

- Codex 默认获得授权，并通过应用 Bundle Identifier 识别。
- 用户可以增加或移除其他应用。
- 只有当前前台来源应用已获授权时，新的剪贴板文字才会被接收。
- 功能启动前已经存在于剪贴板的内容不会被读取。
- 未授权来源不会生成历史记录，也不会触发 TTS。
- 预览区显示检测到的来源应用名称。

## 六、网页正文与 OCR 获取

### 6.1 Chrome 扩展提取正文

首版提供 TypeWhale Chrome 扩展。用户点击浮动工具条中的“朗读网页”后：

1. TypeWhale 向扩展请求当前活动标签页内容；
2. 扩展的 Content Script 读取用户当前可访问、已经渲染的 DOM；
3. 扩展在页面副本上运行 Mozilla Readability，提取标题、作者、语言与正文；
4. 扩展通过 Chrome Native Messaging 把结构化结果交给 TypeWhale；
5. TypeWhale 创建网页类型的 Reader Item，显示预览并直接开始朗读。

规则：

- 只在用户点击“朗读网页”后读取当前标签页；
- 扩展使用最小权限，站点访问权限由 Chrome 和用户管理；
- 不读取浏览历史、其他标签页或后台页面；
- 不绕过登录、付费墙、验证码或网站权限；
- 可以处理用户已登录并且当前已正常显示的动态网页；
- Readability 无法提取可信正文时，不把导航、广告和按钮集合误当作文章直接播放；
- 提取失败时，提示用户改用“读取当前可见文字”或“OCR”；
- 网页正文默认只进入 TypeWhale 当前历史策略，不由扩展长期保存；
- Safari 扩展不在首版范围内，后续可复用相同协议。

### 6.2 macOS 辅助功能兜底

在 Chrome 扩展未安装、未连接或正文提取失败时，可以提供“读取当前可见文字”：

- 使用 macOS Accessibility API 读取前台浏览器暴露的可访问文字；
- 必须获得系统辅助功能权限；
- 结果可能包含按钮、导航或仅当前可见部分；
- TypeWhale 在播放前显示预览与来源说明；
- 该方式是兜底，不作为整篇文章提取的主路径。

### 6.3 本地 OCR

用户点击“OCR”后：

1. 选择框选区域或整个窗口；
2. TypeWhale 截取用户明确选择的画面；
3. 在本机执行 OCR；
4. 显示识别文字预览；
5. 识别成功后直接开始朗读。

规则：

- 默认模式为框选区域；
- 截图只用于本次 OCR，识别结束后删除；
- 历史只保存识别文字，不保存截图；
- OCR 失败或结果可信度过低时，不自动播放，并允许重新截图；
- OCR 可用于禁止复制、Canvas、图片和扫描文档等可见内容；
- OCR 只读取选定画面，不尝试绕过网站访问控制。

### 6.4 获取优先级

网页正文的推荐顺序：

1. Chrome 扩展 + Readability：整篇文章主路径；
2. macOS 辅助功能：当前可见文字兜底；
3. OCR：任何可见内容的最终兜底。

## 七、自动播放与切换规则

### 7.1 复制后自动播放

浮动工具条提供可记忆的勾选项：

> 复制后自动播放

- 勾选：仅当播放器空闲时，新复制内容自动开始朗读。
- 不勾选：只更新预览和最近复制列表，不自动朗读。
- 无论是否勾选，新复制内容都不能打断正在播放的内容。
- 首次开启功能时默认勾选。用户开启该功能，本身就代表其选择使用“复制即听”的主要流程。
- “朗读网页”和“OCR”是明确播放指令，成功取得文字后直接播放，与此勾选项无关。

### 7.2 切换内容

- 新复制内容进入最近复制列表。
- 最近复制列表不是连续播放队列。
- 用户直接点击另一条内容时，明确停止当前朗读，并立即播放所选内容。
- 用户也可以先点击停止，再选择其他内容。

### 7.3 播放控制

工具条提供：

- 播放；
- 暂停；
- 继续；
- 停止；
- 收起；
- 展开；
- 隐藏。

点击停止后，当前选中项和预览内容保留。

## 八、最近内容记录

- 默认最多保留 10 条。
- 默认只保存在内存。
- TypeWhale 退出后，内存记录自动清空。
- 跨重启保存必须由用户主动开启。
- 持久记录只保存在本机 TypeWhale Application Support 目录，并使用仅当前用户可读写的权限。
- 用户可以随时清空记录。
- 连续复制完全相同的内容时，不重复新增记录，只更新当前选择。
- 每条记录分别保存“原始文字”和“朗读文字”，并标记来源类型：剪贴板、网页、辅助功能或 OCR。
- 诊断日志不记录完整复制文字。

## 九、浮动朗读工具条

### 9.1 已选布局

采用已经批准的 **横向胶囊** 设计。

### 9.2 收起状态

显示：

- 拖动手柄；
- 来源应用；
- 当前内容摘要；
- 播放或暂停状态；
- 展开按钮。

### 9.3 展开状态

显示：

- 当前复制内容预览；
- 最近内容列表；
- 朗读网页；
- OCR；
- 音色选择；
- 情绪选择；
- 语速；
- 音量；
- “复制后自动播放”；
- 播放、暂停/继续、停止；
- 清空记录；
- 收起；
- 隐藏。

### 9.4 位置与显示

- 只能从专门的拖动手柄拖动。
- 拖动时不会误触播放控件。
- 每台显示器分别保存浮窗位置。
- 显示器移除、分辨率变化或可用区域变化后，浮窗自动回到可见区域。
- 支持两种显示模式：
  - 功能开启后始终显示；
  - 新内容出现时显示，播放结束后自动隐藏。
- 默认模式：始终显示。
- 自动隐藏模式下，播放停止 5 秒后收起状态的工具条自动隐藏。鼠标停留、展开、暂停或收到新内容时，取消本次自动隐藏。
- 收起只改变界面形态。
- 隐藏只让浮窗离开屏幕，不关闭剪贴板监听。
- 声音 Tab 的功能总开关才会真正停止监听、停止播放并关闭 Reader TTS 活动。

## 十、内容预览与朗读文本处理

原始预览文字与实际朗读文字必须分开保存。

默认处理规则：

- 去除 Markdown 展示符号；
- 保留正文含义与列表顺序；
- 链接只读名称，不逐字符朗读完整网址；
- 默认跳过围栏代码块和缩进代码块；
- 提供“朗读代码”开关；
- 将数字、百分比、货币、运算符和常见公式转成自然语言；
- 保留有意义的中英文术语；
- 将标题、括号、表格、列表符号和重复标点转换成自然停顿；
- 不在英文单词、数字、公式或括号内部切段；
- 优先在自然句子与段落边界切段；
- 长内容绝不静默截断。

例如：

```text
20,000 × 15% = 3,000
```

朗读为：

```text
两万乘以百分之十五，等于三千。
```

跳过的代码会在预览中标记，但不会从原始内容中删除。

## 十一、音色、情绪、语速与音量

Reader Core 根据引擎能力显示控制项，不假定所有模型能力相同。

每个音色需要报告：

- 显示名称；
- 支持语言；
- Speaker ID；
- 支持的语速范围；
- 是否原生支持情绪；
- 支持的情绪列表；
- 模型是否就绪。

首次启用默认值：

- 语速：`1.0x`；
- 音量：`80%`；
- 音色：通过试听与发布门禁选出的原生音色；
- 情绪：模型支持时为“自然”，不支持时禁用。

当当前音色不支持情绪时：

- 情绪控件仍然显示；
- 控件不可操作；
- 显示“当前音色不支持情绪”；
- TypeWhale 不会偷偷改写标点来伪装情绪能力。

## 十二、模型策略

正式功能必须使用原生运行时。

首批候选：

1. 通过 Sherpa C API 运行的 Kokoro multilingual int8；
2. 通过 Sherpa C API 运行的现有 VITS Melo 中英模型；
3. 作为高复杂度对比候选的 ZipVoice distilled int8。

独立原生试听脚本用于比较：

- 自然度；
- 中英文清晰度；
- 停顿质量；
- 首次出声延迟；
- 实时率；
- 内存占用。

模型成为正式默认项前，必须满足：

- 不使用 Python；
- 商业分发许可证完成确认；
- 安装版延迟和真实听感测试通过；
- 失败不会影响 TypeWhale 输入功能。

## 十三、内部架构

采用已经批准的 B 方案：新建独立 Reader Core，不把剪贴板朗读耦合到 OpenClaw。

### 13.1 `ClipboardReaderCoordinator`

负责：

- 监听剪贴板 change count；
- 识别当前前台来源应用；
- 检查应用授权；
- 排除启动前已有内容；
- 去除连续重复内容；
- 创建朗读记录。

### 13.2 `ReaderSourceCoordinator`

负责统一协调内容来源，并把结果规范化为 Reader Item：

- `ClipboardTextSource`：接收授权应用的复制文字；
- `ChromeWebArticleSource`：通过 Native Messaging 接收扩展提取的正文；
- `AccessibilityTextSource`：读取前台浏览器暴露的可访问文字；
- `OCRCaptureSource`：管理区域/窗口截图与本地 OCR；
- 记录来源名称、网页标题与 URL 等必要元数据；
- 不负责文字清理或语音合成。

### 13.3 `ReaderHistoryStore`

负责：

- 管理最近复制内容；
- 限制记录数量；
- 区分内存模式与用户主动开启的持久模式；
- 清空记录。

### 13.4 `ReaderTextPreparer`

负责：

- 将原始复制文字转换为适合朗读的文字；
- 执行代码、Markdown、网址、数字、公式和分段规则；
- 返回预览所需的处理标记。

### 13.5 `ReaderPlaybackCoordinator`

负责：

- 当前选中项和播放状态；
- 新复制内容不打断当前播放；
- 用户主动切换内容；
- 播放当前段时预生成下一段；
- 播放、暂停、继续、停止与进度。

### 13.6 `ReaderTTSService`

负责：

- 暴露原生引擎与音色能力；
- 管理 Helper 生命周期；
- 合成音频段；
- 报告模型状态与失败；
- 不包含剪贴板或界面逻辑。

### 13.7 原生 TTS Helper

负责：

- 在 TypeWhale 主进程之外运行；
- 使用 Sherpa C API 或其他批准的原生接口；
- 使用期间保持模型热加载；
- 支持取消与干净重启；
- 绝不依赖 Python。

### 13.8 `ReaderFloatingPanelController`

负责：

- 收起与展开界面；
- 拖动；
- 每台显示器的位置；
- 显示、隐藏与越界恢复；
- 无障碍支持；
- 只绑定 Reader Core 的展示状态。

### 13.9 声音 Tab 设置

负责：

- 保存产品设置；
- 显示模型状态；
- 控制功能总开关；
- 控制浮窗显示；
- 不直接合成语音，也不直接处理剪贴板文本。

## 十四、数据流

1. 已授权的前台应用向剪贴板写入新的纯文本。
2. `ClipboardReaderCoordinator` 接收文字，创建包含原始文字和来源信息的记录。
3. `ReaderTextPreparer` 生成朗读文字和预览标记。
4. `ReaderHistoryStore` 插入记录。
5. 界面更新预览。
6. 如果开启自动播放且当前空闲，`ReaderPlaybackCoordinator` 选择并播放新内容。
7. 如果当前正在播放，新内容只进入历史，不打断。
8. 用户主动选择另一条内容时，取消当前朗读并播放所选内容。

网页正文流程：

1. 用户点击“朗读网页”。
2. `ChromeWebArticleSource` 请求扩展提取当前标签页。
3. 扩展运行 Readability，并通过 Native Messaging 返回结构化正文。
4. `ReaderSourceCoordinator` 创建网页 Reader Item。
5. `ReaderTextPreparer` 生成朗读文字。
6. 界面显示预览，`ReaderPlaybackCoordinator` 直接开始播放。

OCR 流程：

1. 用户点击“OCR”，选择区域或窗口。
2. `OCRCaptureSource` 截图并在本机识别。
3. 截图被删除，识别文字被创建为 OCR Reader Item。
4. 成功时显示预览并直接播放；可信度过低时等待用户重新截图。

## 十五、状态模型

播放状态：

- 空闲；
- 准备中；
- 播放中；
- 已暂停；
- 停止中；
- 失败。

浮窗状态：

- 显示并收起；
- 显示并展开；
- 已隐藏。

功能状态：

- 已关闭；
- 已开启但模型未就绪；
- 已开启并可用。

网页来源状态：

- 扩展未安装；
- 扩展未连接；
- 扩展已连接；
- 正在提取；
- 提取失败；
- 提取完成。

浮窗显示状态与播放状态相互独立。隐藏浮窗不会停止播放或监听。

## 十六、长内容处理

- 不设置静默截断上限。
- 优先生成第一段。
- 当前段播放时预生成下一段。
- 界面显示段落进度。
- 点击停止或主动切换内容时，取消未完成的合成。
- 超过 50,000 个字符的内容，处理前必须由用户明确确认。
- 超过 500,000 个字符的内容直接拒绝，并提示用户分段复制。

## 十七、失败处理

- 剪贴板监听失败：显示功能状态，不影响 TypeWhale 其他功能。
- 模型缺失：禁用播放、保留预览，并提供安装或修复入口。
- Helper 启动失败：保留文字并显示可操作错误。
- Helper 崩溃：当前请求自动重启一次。
- 再次失败：停止 Reader 播放，进入可恢复的失败状态。
- 单段合成失败：停止当前内容，并允许用户重试。
- 临时音频失败：只停止 Reader 播放。
- 任何失败都不能阻塞 ASR、粘贴、截图、OpenClaw 文字、快捷键或主设置窗口。
- 禁止自动回退到 Python。
- Chrome 扩展不可用：保留播放器功能，并提示安装、重连或使用辅助功能/OCR。
- Readability 无可信正文：不自动播放噪声内容，提供兜底入口。
- Native Messaging 中断：当前请求失败，不影响剪贴板监听和正在播放的内容。
- OCR 失败：删除临时截图，不创建空记录。

## 十八、隐私与安全

- 所有处理在本机完成。
- 复制文字不会发送到服务器。
- 诊断日志不包含完整文字。
- 来源应用必须明确授权。
- 持久历史默认关闭。
- 临时音频在播放或取消后删除。
- 模型包正式分发前必须完成完整性校验与许可证记录。
- Helper 只接收当前选中的朗读文字与音色设置。
- 网页只在用户明确点击后提取。
- 扩展不长期保存网页正文，不读取其他标签页和浏览历史。
- Native Messaging 只接受 TypeWhale 扩展与已安装 TypeWhale Host 的受控通信。
- 网页 URL 在诊断日志中默认脱敏；查询参数和片段不记录。
- OCR 临时截图在识别结束、取消或失败后删除。

## 十九、无障碍

- 所有控件都有无障碍名称和值。
- 键盘焦点依次经过：预览、历史、音色/情绪、语速/音量、自动播放和播放控制。
- 播放、暂停、停止、收起、展开、隐藏和清空都可以用键盘操作。
- 情绪不可用时，明确解释原因。
- 状态不能只依赖颜色表达。
- 收起摘要提供完整文字的无障碍帮助。
- 动效保持克制，并尊重“减少动态效果”设置。
- “朗读网页”和“OCR”按钮具有明确的无障碍名称、状态与错误提示。
- OCR 框选支持键盘取消，并提供区域和窗口模式说明。

## 二十一、验收标准

1. 从声音 Tab 开启功能后显示朗读工具条。
2. 从 Codex 复制文字会生成预览；未授权应用不会。
3. “复制后自动播放”只控制空闲时的自动播放。
4. 播放中复制新内容绝不打断当前朗读。
5. 点击另一条记录会停止当前内容并播放所选内容。
6. 默认最多保留 10 条内存记录，退出 App 后清空。
7. 横向胶囊可以收起、展开、隐藏、恢复、拖动，并在每台显示器保持可见。
8. 音色和语速有效；不支持情绪时，情绪控件保持可见但禁用。
9. Markdown、网址、数字、公式和默认跳过代码符合已批准规则。
10. 长内容按段生成，不静默截断。
11. 正式路径不启动任何 Python 进程。
12. Reader 的任何失败都不能破坏 TypeWhale 现有功能。
13. 点击“朗读网页”可通过 Chrome 扩展提取当前文章正文、显示预览并直接播放。
14. 扩展不读取未主动请求的页面，也不绕过任何网站访问控制。
15. 扩展不可用或提取失败时，用户能清楚转用辅助功能或 OCR。
16. OCR 支持框选区域和整个窗口，默认框选区域；成功后直接播放。
17. OCR 截图在本地识别完成后删除，历史默认只保存识别文字。
18. 剪贴板、网页、辅助功能与 OCR 内容共用同一历史、文本处理和播放体系。
