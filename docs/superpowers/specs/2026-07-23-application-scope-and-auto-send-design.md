# 应用范围中心与粘贴后自动发送设计

**状态：** 已批准，实施中
**日期：** 2026-07-23
**目标：** 用一套清晰的应用选择界面管理“智能整理范围”和“粘贴后自动发送”，保留现有高级整理规则，并保证新增功能不进入实时识别与胶囊展示链路。

## 1. 用户目标

- 用户可以从最近使用和全部已安装应用中选择目标应用。
- 应用展示图标和名称，支持搜索、分类、多选和批量设置。
- “整理范围”和“自动发送”复用同一套应用选择界面。
- 每个应用可以独立选择：
  - 智能整理模式；
  - 关闭自动发送、追加回车或追加 `Command + 回车`。
- 自动发送提供总开关，默认关闭。
- 旧的窗口标题、Bundle ID、口述内容关键词等高级整理能力必须保留。

## 2. 产品边界

### 2.1 本次包含

- 新建“应用范围”管理窗口。
- 替换现有固定表格式“自动模式范围”弹窗。
- 为普通听写增加按应用配置的粘贴后按键。
- 迁移并展示旧的智能整理自动范围配置。
- 根据屏幕可用空间自适应窗口尺寸。

### 2.2 本次不包含

- 不修改 ASR、VAD、实时缓存、Final ASR、重叠矫正和文本整理算法。
- 不修改主胶囊、闪念胶囊、OpenClaw 胶囊和旁路胶囊的数据或绘制。
- 不为闪念、OpenClaw、翻译、手动复制增加自动回车。
- 不改变粘贴文本内容，也不把回车字符拼进文本。

### 2.3 禁止事项

- 禁止让设置页扫描应用的工作在录音期间持续运行。
- 禁止让 UI 保存状态直接参与粘贴执行。
- 禁止在粘贴失败、文本为空、任务取消或目标应用变化后发送回车。
- 禁止把“整理范围”开关与“自动发送”开关联动。
- 禁止把旧规则静默转换为语义不同的新规则。

## 3. 界面设计

采用已批准的 A+C 合并方案。

### 3.1 页面结构

- 顶部：
  - 标题“应用范围”；
  - `整理范围 / 自动发送` 分段切换。
- 左侧：
  - 最近使用；
  - 沟通；
  - 办公；
  - 开发；
  - 浏览器；
  - 全部应用；
  - 通用高级规则。
- 中间：
  - 应用图标、名称、最近使用信息；
  - 多选状态；
  - 当前整理模式或发送动作；
  - 搜索和“仅看已配置”筛选。
- 右侧：
  - 当前应用的默认设置；
  - 整理模式下显示该应用的高级范围规则；
  - 自动发送模式下只显示关闭、回车、`Command + 回车`。
- 底部：
  - 当前选择摘要；
  - 取消和保存按钮。

### 3.2 两种入口

- 从“智能 > 自动范围”进入时，默认选中“整理范围”。
- 从“常用 > 粘贴与发送 > 应用范围”进入时，默认选中“自动发送”。
- 两个入口打开同一个页面控制器，只改变初始分段。
- 切换分段不会覆盖或重置另一个分段的未保存编辑；点击保存时分别写入对应配置。

### 3.3 自适应窗口

- 页面使用可调整大小的原生 sheet/window，不继续使用固定 `700 × 326` 内容区。
- 推荐初始内容尺寸为 `960 × 620` 点。
- 最小内容尺寸不低于 `820 × 520` 点。
- 最大尺寸取当前屏幕 `visibleFrame` 的 90%，必须避开菜单栏、Dock、刘海和副屏不可见区域。
- 小屏幕下：
  - 左侧分类栏保持固定窄宽；
  - 中间应用列表和右侧规则区允许缩窄；
  - 达到最小宽度后优先将右侧详情改为可展开区域，不压缩到不可读；
  - 应用列表和规则区分别滚动。
- 标题、分段切换、搜索、保存和取消按钮始终可见，不随内容滚走。
- 记住用户上次调整后的窗口尺寸，但恢复时必须重新限制到当前屏幕可用范围。

### 3.4 选择与批量操作

- 勾选多个应用后可以批量设置整理模式或发送动作。
- 单击应用行时，右侧显示该应用详情。
- 批量修改只影响当前选中的功能分段。
- 未配置的应用默认显示：
  - 整理范围：未指定，继续走现有通用规则和 fallback；
  - 自动发送：关闭。

## 4. 应用目录

新增只服务设置界面的 `ApplicationCatalog`。

- 数据来源：
  - 最近实际成为 TypeWhale 目标的应用；
  - `/Applications`；
  - `~/Applications`；
  - 系统可用应用目录。
- 每条应用记录至少包含：
  - Bundle ID；
  - 展示名称；
  - Bundle URL；
  - 应用图标；
  - 分类；
  - 最近使用时间。
- Bundle ID 是配置匹配的唯一主键；名称只用于展示和兼容旧关键词规则。
- 同一 Bundle ID 去重。
- 应用枚举和元数据读取只在页面打开时执行，并使用独立队列。
- 图标按需加载并缓存；主线程只接收已准备好的展示快照。
- 页面关闭后停止未完成的展示加载；不得创建常驻扫描、Timer 或录音链路观察者。
- 无法读取分类时归入“其他”，不得因此隐藏应用。

## 5. 整理范围数据设计

### 5.1 保留现有能力

现有 `SmartRewriteAutoConfiguration` 和以下语义继续有效：

- 目标应用名称；
- Bundle ID；
- 窗口标题；
- 本次口述内容；
- 关键词；
- 整理模式；
- 启用状态；
- fallback 模式；
- 规则顺序。

### 5.2 新增应用默认项

为应用级配置增加明确的 Bundle ID 默认项，而不是继续要求用户手写逗号关键词。

- 每个应用最多一个默认整理模式。
- 高级规则用于更精确的窗口标题或口述内容条件。
- 匹配顺序：
  1. 已启用的高级规则，保持原有顺序；
  2. 当前 Bundle ID 的应用默认模式；
  3. 现有 fallback 模式。
- 旧规则原样迁移到“通用高级规则”；保存新页面时不得丢失或改序。
- 旧配置解码失败时继续使用当前默认配置，并记录诊断日志，不得影响普通听写。

## 6. 自动发送数据设计

新增独立配置，不与智能整理规则共用存储：

```text
AutoSendConfiguration
├── isEnabled：总开关，默认 false
└── actionsByBundleID
    └── Bundle ID → none / returnKey / commandReturn
```

- `none` 表示该应用不自动发送。
- 配置只保存 Bundle ID 和动作，不保存应用图标。
- 应用卸载后配置保留；重新安装同 Bundle ID 后自动恢复。
- 未知枚举值按 `none` 处理。
- 恢复默认只清除自动发送配置，不修改整理范围。

## 7. 执行架构

### 7.1 分层

```text
设置界面
→ ApplicationCatalog（只提供应用展示数据）
→ RewriteScopeStore / AutoSendStore（分别保存）

普通听写完成
→ SpeechInputCoordinator（确定冻结的目标应用）
→ AutoSendPolicy（只读取配置并返回动作）
→ PasteCoordinator（串行粘贴）
→ 粘贴事件已成功发出且目标焦点仍正确
→ PostPasteKeyEmitter（回车或 Command + 回车）
```

### 7.2 责任边界

- `ApplicationCatalog` 不读取录音状态，不执行粘贴。
- 设置 UI 不读取 `SpeechSession`、实时缓存或胶囊状态。
- `AutoSendPolicy` 不发系统事件，只根据总开关、Bundle ID 和任务类型返回动作。
- `SpeechInputCoordinator` 在普通听写进入粘贴队列前确定动作。
- `PasteCoordinator` 只接收已确定的动作，不直接读取 `UserDefaults`。
- `PostPasteKeyEmitter` 只负责构造并发送键盘事件。

### 7.3 发送门禁

同时满足以下条件才允许追加按键：

1. 总开关开启；
2. 本次是普通听写粘贴；
3. 最终文本非空；
4. 目标应用存在且 Bundle ID 有明确动作；
5. 剪贴板内容已通过现有 readiness gate；
6. `Command + V` 或直接输入事件已经成功发出；
7. 发送追加按键前，前台应用仍是录音开始时冻结的目标应用。

任一条件不满足时只保留正常粘贴，不发送回车。

### 7.4 时序与失败处理

- 追加按键属于同一个 `PasteCoordinator` 串行请求，不能跨到下一条听写任务。
- 粘贴后使用很短的可配置间隔发送追加按键，具体时序在实现 Task 的代码走读和 RED 测试中确定，不在 UI 层等待。
- 若目标焦点变化或系统事件创建失败：
  - 不重试回车；
  - 不撤销已经成功的文本粘贴；
  - 记录原因；
  - 队列继续处理下一项。
- 自动发送失败不得显示为识别失败，也不得卡住录音状态机。

## 8. 设置入口

在“常用”页新增“粘贴与发送”Section：

- “粘贴后自动发送”总开关，默认关闭；
- “应用范围”按钮；
- 简短说明：仅普通听写成功粘贴后生效。

“智能”页原“自动范围”入口改名为“应用范围”，仍位于智能整理相关 Section。

## 9. 可观测性

仅记录结构化状态，不记录用户文本：

- 配置决策：总开关、目标 Bundle ID、选中的动作；
- 门禁结果：disabled、no-rule、excluded-task、focus-changed、paste-failed；
- 系统事件结果：return-posted、command-return-posted、event-create-failed；
- 应用目录：扫描耗时、应用数量、取消状态。

日志不得包含口述原文、剪贴板内容或提示词。

## 10. 验收标准

### 10.1 界面

1. 两个设置入口打开同一页面，并进入正确分段。
2. 最近应用和已安装应用显示图标、名称和分类。
3. 搜索、多选、仅看已配置和批量设置可用。
4. 旧的窗口标题、内容关键词规则可查看、编辑和保存。
5. 在内建屏、副屏和较小窗口下，页面不超出可见区域；关键按钮始终可见。
6. 调整窗口尺寸后布局不重叠、不截断，列表和规则区可独立滚动。

### 10.2 自动发送

1. 新安装或恢复默认后，总开关关闭，所有应用都不会追加按键。
2. 微信配置“回车”后，普通听写成功粘贴文本并发送回车。
3. 需要 `Command + 回车` 的应用能收到正确组合键。
4. 未配置应用只粘贴文本。
5. 粘贴失败、目标关闭、焦点改变、空文本和任务取消时不发送回车。
6. 闪念、OpenClaw、翻译和手动复制不发送回车。
7. 开启或关闭 Final ASR 不改变自动发送规则。

### 10.3 稳定性与回归

1. 不打开设置页时，不新增应用扫描、Timer、图标加载或录音观察者。
2. 录音、实时预览、主胶囊刷新和最终文本产出没有新增等待。
3. 连续十次普通听写的粘贴顺序与自动按键顺序一致。
4. 自动发送失败不会阻塞下一次录音。
5. 旧智能整理范围升级后行为保持一致。
6. 快捷键、剪贴板保护、目标应用冻结和历史记录无回归。

## 11. 回退策略

- 自动发送总开关默认关闭，可立即停止新行为。
- 自动发送存储和整理范围存储相互独立，可单独回退。
- 新应用范围页面上线前保留旧规则的完整解码和保存测试。
- 如新页面存在严重问题，可恢复旧入口 UI；不得删除或重置用户已有规则。
- 追加按键执行必须是独立小组件，回退时不修改 `PasteCoordinator` 原有剪贴板保护流程。
