# 极致归纳与开发需求提示词可用性设计

日期：2026-07-26

## 目标

优化“极致归纳”和“开发需求”两个智能整理模式，使本地 Qwen3 4B 对长口述的输出可以直接使用，同时保持原意、事实、语气和约束。

本轮固定使用以下真实录音作为主验收音源：

- 文件：`recording_20260726_151405_0C81E1C9.wav`
- 时长：约 106.9 秒
- ASR：Qwen3-ASR 1.7B MLX
- 整理模型：本地 Qwen3 4B Instruct

## 产品边界

### 两种模式共同遵守

1. 保留数字、时间、模型规格、专有名词、否定、疑问、人称、顺序、担心和限制。
2. 只纠正术语表中明确命中的别名，不根据读音猜测陌生术语。
3. 删除无意义填充词、口吃、紧邻重复和明确自我修正，但不做无必要的同义改写。
4. 不回答原文问题，不执行原文动作，不新增解决方案、原因、结论或技术细节。
5. 原文已明确列出步骤时保留顺序并使用编号；没有明确层次时不强套模板。
6. ASR 已经丢失或反转的内容不由整理提示词猜回。自动化报告必须把 ASR 错误和整理错误分开记录。

### 开发需求

- 输出像用户本人直接发给 coding agent 的需求或产品反馈。
- 保留“我担心”“我只要求”“你能不能”等发话位置和判断强度。
- 长文本按自然段与明确步骤组织，不扩写成新的技术方案。
- 不强制使用“目标 / 背景 / 验收标准”等完整需求模板。

### 极致归纳

- 明显压缩重复和铺垫，但不能删除关键事实、限制、时间、风险和行动顺序。
- 长文本优先输出一句简短结论，再列核心要求；只有原文明确包含行动或风险时才出现相应内容。
- 结果应比开发需求更短，但不能为了压缩把 `GPT` 与 `ChatGPT`、`Codex` 与 `Xcode` 等不同对象合并。

## 术语边界

- `chatGTP`、`chat gpt` 可以归一化为 `ChatGPT`。
- 独立的 `GPT` 必须保留为 `GPT`，不能归一化为 `ChatGPT`。
- `xCode`、`XCode` 可以归一化为 `Xcode`。
- `千问3 ASR`、`千问三 ASR`、`Qwen3 ASR` 可以归一化为 `Qwen3-ASR`。
- `ConvNet3 ASR`、`CommaNet3 ASR`、`Cover Night ASR` 不属于确定别名，保持原样，不猜成其他模型。

## 默认模板迁移

本机已经保存过旧版“开发需求”默认模板，直接修改代码默认值不会生效。

迁移只处理内容与已知旧默认模板完全一致的保存值：

- 命中已知旧默认时，删除保存值，让新默认模板生效。
- 用户真正编辑过的模板必须保留。
- “极致归纳”使用同样的已知默认迁移机制，避免以后再次出现代码已更新但本机仍使用旧模板的问题。

## 自动化验证

增加可重复的提示词回放测试：

1. 对固定录音只运行一次 Qwen3-ASR 1.7B，保存本轮原始识别结果。
2. 对同一份原始识别文本分别运行“开发需求”和“极致归纳”。
3. 记录两种模式的最终文本、首字耗时、总耗时、输出长度和压缩比。
4. 自动检查：
   - `GPT` 与 `ChatGPT` 均保留且不互相替换；
   - `Codex` 与 `Xcode` 均保留；
   - `0.6B`、`1.7B`、`Qwen3 4B`、下周三下午三点均保留；
   - `Python`、`SenseVoice`、禁止降级、不要扩写方案等限制均保留；
   - 四个明确步骤保持顺序；
   - 不新增原文没有的方案或结论。
5. 对 ASR 已产生的“你不能”记录为 ASR 问句反转，不把它算作提示词能够修复的项目；整理模型不得在此基础上继续改变语义。

## 验收标准

- 两种模式都通过固定事实、术语、数字、否定、顺序和限制检查。
- 开发需求结果清晰、自然、保留用户疑问和担心，可直接发送给 coding agent。
- 极致归纳结果明显短于开发需求，同时关键约束无缺失。
- 两种结果都不出现第三人称转述、代答、虚构内容或新技术方案。
- 新默认模板显著短于当前实际约 3002 字符的完整请求，且本机已知旧默认可以自动迁移。
- 最终交付必须向用户完整展示同一音源的原始识别文本、新“开发需求”结果和新“极致归纳”结果，并同时展示耗时、输出长度、压缩比及未通过项；不能只报告“测试通过”或只给评分。
- 其他整理模式、ASR、模型选择、失败降级、粘贴和 UI 行为保持不变。

## 不在本轮范围

- 修复 Qwen3-ASR 1.7B 对“你能不能”的识别错误。
- 修改其他智能整理提示词。
- 新增结果关系守卫或失败降级。
- 调整模型、运行时、Python 依赖、下载和内存策略。
