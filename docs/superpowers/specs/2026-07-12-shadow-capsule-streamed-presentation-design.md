# 三胶囊迁移与候选流式展示设计

## 状态

- 日期：2026-07-12
- 状态：产品方向已批准，等待实施计划
- 当前阶段：主计划 Stage 8 已完成；Stage 9A / Task 13A 待实现

## 核心目标

第二个胶囊最初是安全迁移跑道：旧胶囊保证日常可用，新架构在旁路实时验证，成熟后才讨论接管正式预览。当前实践暴露出一个职责冲突：同一个旁路胶囊既要忠实呈现 Provider 的真实批次和卡顿，又要展示优化后的未来产品体验。这两个目标不能由同一视图同时满足。

本设计把它们拆成三条并行视图：

- 原胶囊回答“当前产品是否仍然正常可用”。
- 旁路1回答“Provider 和新架构实际上产生了什么”。
- 旁路2回答“这些真实结果经过候选展示层后，未来产品体验是什么”。

## 产品结构

### 原胶囊：生产权威

- 保持当前位置、视觉、预览、final 和粘贴行为。
- 不读取旁路1或旁路2状态，不受其失败、动画和窗口生命周期影响。
- 在 Stage 13B 获得独立切换批准之前不得修改。

### 旁路1：真实技术胶囊

- 沿用现有 `ShadowPreviewCoordinator/Presenter/View`。
- 直接呈现最新 `PreviewViewState`，保留 MiMo 约 2 秒首快照、后续约 4 秒批次及 SSE chunk 快速突发的真实特征。
- 不加入逐字打字机来美化节奏。
- 可增加不改变文字时序的真实事件标识，例如 revision/chunk 计数或每次状态到达的短脉冲；具体视觉需单独设计复核。
- 继续承担首字、修订、批次、失败和跨 session 诊断证据。

### 旁路2：候选产品胶囊

- 新建独立 Presenter/View/Coordinator 或复用明确抽出的候选展示组件，不共享旁路1窗口实例和动画状态。
- 数据只来自同一新核心 `PreviewViewState`，不得直接读取 MiMo、WAV、SSE 或旧 `SpeechSession` 字段。
- 可以对已经真实到达的新增文字做有界逐字推进，验证未来正式胶囊体验。
- 不生成 Provider 尚未返回的文字；无新状态时目标文本不增长。
- 非前缀修订必须干净替换，不把新旧内容按位置混合。

## 候选展示缓冲

新增纯 Swift、无 AppKit 的 `CandidateStreamTextBuffer`：

- `targetText` 是最新 ViewState 的完整真实文本。
- `displayedText` 是旁路2当前可见文本。
- 前缀增长时只动画真实新增尾部。
- 待显示尾部不超过 24 字时，以约 50ms/字推进。
- 积压超过 24 字时立即追赶，只保留最后 24 字动画，避免长期落后。
- 非前缀更新视为修订，干净切换到新目标的有界可读前缀，再动画真实剩余尾部。
- failure、cancel、completed、隐藏和 session 变化会停止定时器并清空旧状态。

逐字节奏是客户端对已到达内容的产品呈现，不得描述为服务端逐字识别。旁路1和原始时间诊断必须继续暴露真实 Provider 节奏。

## 布局与生命周期

- 三个胶囊仅在“旁路预览（实验）”开启时同时出现；关闭时只保留原胶囊。
- 旁路1和旁路2相对原胶囊布局必须经过屏幕安全区计算，不能遮挡彼此、菜单栏或刘海。
- 第一版优先让旁路2复用原胶囊已验证的尺寸、排版和文字节奏，减少视觉变量；是否重新设计更符合 stable/volatile 的外观留给后续独立 UI 决策。
- 两个旁路必须各自拥有和清理订阅、Timer、Task 与窗口；隐藏或连续新会话不能复活旧状态。
- UI 消费速度不能反压 Provider、录音 fan-out、Session、Reducer 或 Projector。

## 数据流

```text
Provider → TranscriptionSession → TranscriptReducer → PreviewStateProjector
                                                ├─→ 旁路1：真实技术展示
                                                └─→ 旁路2：候选产品展示

旧生产预览链路 ───────────────────────────────────→ 原胶囊
```

旁路1与旁路2必须各自获得可合并最新状态订阅，不能由一个 UI 消费者转发给另一个，避免动画或窗口阻塞传播。

## 可观察验收标准

1. MiMo 一次请求快速返回多个 delta 时，旁路1忠实呈现实际状态节奏并记录 revision；旁路2对真实新增文本形成连续可见增长。
2. SSE没有新内容时，旁路2不产生任何新字。
3. 快速到达40个真实字符时，旁路2追赶后最多保留24字动画，最终严格等于最新 ViewState。
4. 非前缀修订不出现新旧文字混合；旁路1仍展示实际修订结果。
5. 取消、失败、关闭实验和连续第二轮录音后，两个旁路的旧Task、Timer和文字均不能继续更新。
6. 20秒和2分钟安装版测试中，原胶囊、final、整理和粘贴零退化。
7. 亮色/暗色、菜单栏安全区、三窗口相对位置、文字节奏、闪烁、跳变和上下文保持通过design-review。

## 实现边界

### In scope

- 主计划 Stage 8 正式收口。
- 新增旁路2及其纯展示缓冲、Presenter/View/Coordinator和设置生命周期接线。
- 为两个旁路提供独立状态订阅和诊断时间点。
- 自动化、真实安装版、设计质量和回滚验证。

### Out of scope / Do not touch

- 不改变 MiMo 快照调度、协议、Keychain、计费或Provider状态语义。
- 不改变旧胶囊、final、VAD、整理、翻译、历史、OpenClaw和粘贴。
- 不让旁路2接管正式位置，不删除旁路1或旧预览。
- 不把视觉逐字推进宣称为持续PCM或服务端逐字输出。

## 测试策略

- TDD纯缓冲：前缀增长、24字追赶、逐字推进、无输入不增长、非前缀修订、跨session清理。
- 生命周期：两套独立订阅、单一定时器、隐藏/失败/取消/完成清理、晚到事件隔离。
- 布局：三窗口在多种屏幕宽度与安全区内不重叠。
- 回归：MiMo Provider/SSE、Reducer、Projector、Session、Shadow Isolation、旧胶囊缓冲、final chunk和音频fan-out。
- 代码完成后更新版本与开发记录，执行唯一构建入口，覆盖安装 `/Applications/TypeWhale Pro.app`，验证签名并完成真实三胶囊复核。

## 回滚

关闭实验设置必须立即销毁旁路1和旁路2。代码级回滚可以移除旁路2及候选展示缓冲，恢复当前单旁路状态；旁路1、新核心、旧胶囊和生产链路不受影响。
