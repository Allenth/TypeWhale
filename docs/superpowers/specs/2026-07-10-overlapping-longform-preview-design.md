# TypeWhale 重叠校正预览与长录音增量输出实验设计

> 状态：待用户书面复核后进入实施计划
>
> 日期：2026-07-10
>
> 适用范围：TypeWhale Pro macOS 当前 SenseVoice 非流式预览链路

## 1. 决策摘要

本实验采用方案 C：保留当前 `10–18s` 分块作为音频与计算资源边界，把分块边界降级为 candidate seam（候选接缝）；系统使用跨边界音频窗口、结构化识别结果和 `PreviewTranscriptReducer`（预览文本状态归约器）校正接缝并确认稳定片段。

实验提供两个默认关闭的设置：

1. “重叠校正预览（实验）”：只替换胶囊预览策略，普通最终识别保持不变。
2. “长录音增量输出（实验）”：依赖并自动启用第一个设置；延长录音时长，停止时使用权威增量转录作为最终原文，不重新识别整段录音。

旧链路必须原样保留。关闭实验设置后，不创建实验管线、不生成跨块校正任务、不改变最终文本来源。

## 2. 目标

### 2.1 预览目标

- 保留首个约 `0.3s`、后续约 `0.5s` 的快速可见反馈。
- 已确认前文永不反复替换。
- 只校正尚未确认的尾部。
- 相同显示文本不重复发布、不重复触发胶囊动画。
- 分块接缝不采用朴素字符串直接拼接。
- 时间戳有效时优先按音频时间轴对齐；缺失时依次退回词元和用户可见字符对齐。

### 2.2 长录音目标

- 支持至少 1 小时的真实场景测试。
- 第一轮设置 4 小时 safety cap（安全上限），避免忘记停止后无限写盘。
- 确认片段持续持久化，不能把一小时正文只保存在内存。
- 停止时只处理最后未确认尾部和尚未完成的边界任务，不对整段录音执行一次性 ASR。
- 最终原文由 confirmed segments（已确认片段）与 reconciled tail（校正尾部）组装。
- 完整原始录音始终保留，可用于故障恢复和离线复核。

## 3. 非目标

- 本实验不把本地流式模型或在线流式服务接入生产路径。
- 不全面拆分 `SpeechInputCoordinator`；只迁出实验预览所需的调度与状态归约职责。
- 不删除当前 `committedPreviewText + latestPreviewText` 旧路径。
- 不使用 `CapsuleTextBuffer.displayedDraft` 作为权威转录来源。
- 不承诺第一轮实验已经适合商业发布或永久替代完整录音 final ASR（最终语音识别）。
- 不把 Whisper 论文中的准确率或延迟数字外推为 SenseVoice 已验证结果。
- 不在本实验中实现双麦克风、多会话或 Provider fallback（服务提供器故障切换）。

## 4. 当前基线与必须保护的路径

当前 `AudioRecorder`：

- 首次约 `0.30s` 产生快照，后续约每 `0.50s` 产生快照。
- 当前块达到约 `10s` 后等待 VAD（语音活动检测）停顿提交。
- 连续语音到约 `18s` 强制提交。

当前 `SpeechInputCoordinator`：

- 使用 `committedPreviewText + latestPreviewText` 生成胶囊草稿。
- 普通预览请求 latest-only（只保留最新请求），块最终快照进入独立 FIFO（先进先出队列）。
- realtime ASR（实时识别）和 final ASR（最终识别）共享一个 `NativeSenseVoiceBridge` 串行执行环境。

必须保护的普通路径：

```text
快捷键开始录音
→ 当前实时预览
→ 用户停止或现有自动完成
→ 完整录音 final ASR
→ 现有清理、翻译、智能整理、保存和粘贴
```

当两个实验设置都关闭时，上述路径的状态、时长、文本来源、错误处理和用户可见行为必须保持不变。

## 5. 设置与模式关系

### 5.1 重叠校正预览

- 设置名称：“重叠校正预览（实验）”。
- 位于现有“胶囊实时预览”设置下方。
- 默认关闭。
- 关闭时不初始化实验管线。
- 关闭时普通录音仍使用当前 6 分钟上限和完整录音 final ASR。
- 开启时自动保持现有“胶囊实时预览”为开启状态；如果用户关闭基础实时预览，两个实验设置同步关闭。
- 只在当前 Session（会话）实际解析为 SenseVoice 非流式 Provider（服务提供器）时可用；Qwen3-ASR 或其他不支持该实验协议的 Provider 不得误入实验管线。

### 5.2 长录音增量输出

- 设置名称：“长录音增量输出（实验）”。
- 默认关闭。
- 开启时自动启用“重叠校正预览（实验）”。
- 如果关闭重叠校正预览，长录音增量输出必须同步关闭，不能形成无校正的增量最终输出。
- 使用初始 4 小时安全上限。
- 不响应普通停顿自动完成和 5 分钟无文本结束。
- 仍响应用户手动停止、4 小时安全上限、音频输入路由失效、磁盘不足和写入失败。

## 6. 模块边界

### 6.1 `PreviewRecognitionResult`（预览识别结果）

不可变、可测试的数据值，至少包含：

- `text`
- `tokens`
- 可选 `tokenTimestamps`
- `audioRange`
- `requestID`
- `sessionID`
- `chunkID`
- `sourceLane`

### 6.2 `BoundaryCenteredPreviewPlanner`（边界中心预览规划器）

纯逻辑组件，职责是：

- 接收音频进度、VAD 状态和当前分块状态。
- 产生 fast snapshot（快速快照）计划。
- 在 `10s + 停顿` 或 `18s` 时提出候选分块边界。
- 计算跨边界校正窗口的时间范围。
- 在低置信度时产生最大约 `22.5s` 的 recovery window（恢复校正窗口）计划。

它不写文件、不调用 ASR、不保存文字。

### 6.3 `ExperimentalRealtimePreviewPipeline`（实验实时预览管线）

应用层门面，职责是：

- 接收带 session identity（会话身份）的音频快照与边界事件。
- 管理 Fast Lane（快速预览通道）和 Reconciliation Lane（校正通道）。
- 执行请求准入、优先级、latest-only 合并、超时和 stale callback（过期回调）拒绝。
- 把结构化结果交给 Reducer（状态归约器）。
- 输出单一 `PreviewTranscriptState`（预览转录状态）。

### 6.4 `PreviewTranscriptReducer`（预览文本状态归约器）

纯状态机，是实验路径唯一文本权威，职责是：

- 维护 confirmed segments（已确认片段）。
- 维护 mutable tail（可修改尾部）。
- 对齐跨边界结果。
- 决定确认边界是否推进。
- 保证已确认片段不可修改。
- 抑制相同显示文本的重复发布。
- 生成持久化事件和胶囊 ViewState（视图状态）。

### 6.5 `IncrementalTranscriptStore`（增量转录存储器）

负责：

- 在用户级 Application Support（应用支持目录）中按 `sessionID` 建立会话目录。
- 原子保存会话元数据。
- 以 append-only（只追加）记录保存确认片段、修订、Provider（服务提供器）信息和时间范围。
- 保存最终组装结果与 degraded（降级）状态。
- 不在音频实时 callback（回调）中执行磁盘重活。

### 6.6 Presenter（展示器）边界

普通实验预览胶囊接收：

```text
confirmedText + mutableTailText
```

Presenter（展示器）和 `CapsuleTextBuffer` 只能控制动画，不得改变权威文本内容。

长录音模式不得每 `0.5s` 重新拼接全部已确认正文。权威状态保存 Segment（转录片段）集合，胶囊 ViewState（视图状态）只提供有界的 recent confirmed context（最近确认上下文）与 mutable tail（可修改尾部），同时携带累计确认字数。完整正文只在持久化重放或停止组装时生成。

## 7. 音频与文本数据流

```text
AudioRecorder
  ├─ Fast snapshot plan
  │    → Preview scheduler
  │    → SenseVoice structured result
  │    → Reducer mutable tail
  │
  └─ Candidate chunk boundary B
       → retain left context
       → collect right context
       → boundary-centered correction window
       → SenseVoice structured result
       → alignment + agreement
       → confirmed segment / mutable seam
       → append-only persistence
```

长录音停止时：

```text
停止接收新音频
→ 丢弃尚未开始的过时 fast 请求
→ 完成或重建未完成的边界校正任务
→ 校正最后未确认尾部（最大使用有界恢复窗口）
→ confirmed segments + tail
→ 写入最终增量 transcript
→ 作为当前后续清理/翻译/智能整理/保存/粘贴链路的 raw source（原始来源）
```

长录音模式跳过完整录音 final ASR，但不绕过现有下游长度、费用和输入安全保护。

## 8. 边界中心校正算法

### 8.1 分块职责

`10–18s` 分块只负责：

- 限制当前快速快照的音频增长。
- 限制内存和重复识别成本。
- 提出候选边界 B。

块结束不再等于文字永久提交。

### 8.2 跨边界上下文

候选边界 B 产生后：

- 保留 B 之前的左侧音频上下文。
- 继续采集 B 之后的右侧音频上下文。
- 初始校正窗口目标由实现审查修正为约 `22.5s`，并在 B 后获得约 `9.5s` 右侧上下文后提交；这是为了保证连续 `18s` 硬分块对应的校正窗仍有重叠，不留下未校准空洞。
- 录音开始、停止或短块导致上下文不足时，允许使用不对称但显式标记的有界窗口。
- 普通窗口冲突时继续使用最大约 `22.5s` 的恢复校正窗口，并显式标记 recovery（恢复）状态。

### 8.3 接缝选择

接缝证据按以下顺序使用：

1. VAD 停顿时间范围。
2. 具有绝对音频时间的相同或兼容词元序列。
3. 无时间戳时的词元序列对齐。
4. 无词元时按 Swift `Character`（用户可见字符）进行序列对齐。
5. 标点只能辅助评分，不能独立决定接缝。

每次对齐必须从识别结果的相邻连续区域产生，不能越过第一次实质冲突后继续确认。

### 8.4 上下文保护

- 不在校正窗口左边缘或右边缘直接选择接缝。
- 优先选择同时拥有左右上下文的 center-safe region（中心安全区）。
- 如果接缝落在长句中且两个结果不一致，确认边界保持不动。
- 低置信度首先触发恢复校正，不强制拼接。
- 恢复后仍不一致时，保留最佳候选并标记 degraded；完整音频和候选证据必须保留，不能静默声称高置信度。

### 8.5 不累积污染的不变量

- 每个识别窗口始终读取原始音频，不把前一轮文字作为下一轮 ASR 输入。
- 已确认片段不可修改。
- 未确认尾部可以整体替换。
- 时间范围使用会话单调时间，不能由字符串长度推导。
- 单个接缝的低置信度不得改变后续窗口的绝对音频坐标。

## 9. 结构化 SenseVoice 结果

保留当前仅文本 C API（C 语言应用程序接口），供旧路径继续使用；新增实验专用结构化 API，完整复制 sherpa-onnx result 生命周期内的：

- `text`
- `tokens_arr`
- `timestamps`（可选）
- `count`

Swift 层必须在原生 result 被销毁前取得自有副本。

能力规则：

- `timestamps == nil` 或数量不匹配时，结果仍有效，但 capability（能力）标记为无时间戳。
- 时间戳必须为有限值、单调不下降，并与音频窗口范围相容；否则降级为无时间戳。
- tokens（词元）为空时退回文本对齐。
- 结构化 API 失败不能影响旧文本 API。

## 10. 调度、并发与背压

### 10.1 优先级

同一会话内：

```text
停止时尾部收口
> 尚未完成的边界校正
> 最新快速预览
```

普通模式的完整录音 final ASR 保持现有产品优先级，不因实验管线堆积隐藏请求。

### 10.2 准入规则

- 同一 Native SenseVoice runtime（原生运行环境）一次只准入一个识别任务。
- Fast Lane 只保留最新待处理请求。
- 边界校正任务按音频时间有序，不允许静默覆盖。
- 管线只向共享原生队列提交当前准入任务，避免在不可取消的底层队列中预埋大量工作。
- `timeout`（超时）只代表上层停止等待，不得记录为底层已经取消。
- callback（回调）必须通过 `sessionID + epoch + requestID` 验证，过期结果不得修改状态。

### 10.3 跟不上实时速度时

- 优先暂停 Fast Lane，给边界校正让出计算资源。
- 边界任务的时间范围和状态持久化，可在停止后从完整音频重建窗口继续处理。
- 不因实时积压丢失整块正文。
- backlog（积压）数量、最老任务延迟和 ASR realtime factor（实时系数）必须记录。
- 停止时若仍有必要边界任务，界面保持“正在完成转录”，不能提前粘贴不完整正文。

## 11. 长录音生命周期

### 11.1 开始

- 创建 session directory（会话目录）和元数据。
- 记录实验参数、模型版本、输入设备 UID、采样率和开始时间。
- 音频文件与转录证据使用同一个稳定 `sessionID`。

### 11.2 录制中

- 普通停顿不自动结束。
- 5 分钟没有新文本不自动结束。
- 每个确认片段原子追加持久化。
- 每次持久化失败进入可见错误状态，但音频录制优先继续，除非音频本身无法安全写入。
- 定期检查可用磁盘空间；达到安全阈值时停止并保留已有内容。

### 11.3 停止

- 先停止音频写入并确认文件完整。
- 停止产生新 fast 请求。
- 完成边界任务和尾部校正。
- 组装最终增量正文。
- 写入最终会话状态。
- 将该正文作为当前 workflow（工作流）的原始识别文本继续处理。

### 11.4 异常恢复

- App 异常退出后，完整音频、会话元数据和已确认片段仍存在。
- 未完成会话不得被标记为完整成功。
- 后续恢复可以从最后 confirmed time（确认时间）重新提取有界音频，不必重跑已确认的一小时前文。

## 12. 错误与降级语义

必须区分：

- `failed`：请求失败。
- `timedOut`：上层等待超时，底层可能仍运行。
- `cancelled`：底层确认取消。
- `stale`：结果属于旧会话或旧 epoch。
- `degraded`：有输出但证据不足。

行为规则：

- Fast Lane 失败：保留当前可修改尾部，等待下一快照。
- 单次边界校正失败：保留任务并允许有界重试/停止后重建。
- 时间戳无效：退回词元或字符对齐。
- 尾部校正失败：使用最新非空候选作为 degraded 尾部，同时保存对应音频和错误；不得删除已确认片段。
- 持久化失败：日志与 UI 必须可见；最终结果不能被标记为完整持久化成功。
- 实验管线出现不可恢复内部错误时，普通预览模式可以停止实验投影并保留旧 final ASR；长录音模式必须继续保存音频并明确提示增量正文需要恢复，不能静默切换成一小时整段 ASR。

## 13. 可观测性与实验指标

每个会话至少记录：

- 实验开关状态和参数版本。
- 快速请求数、合并数、失败数和延迟。
- 候选边界类型：VAD 或 18 秒硬边界。
- 校正窗口范围、时长和恢复窗口次数。
- 时间戳可用率。
- 接缝对齐方式和置信度。
- 每次正文 revision（修订）的字符范围。
- confirmed latency（确认延迟）。
- ASR realtime factor（实时系数）。
- backlog（积压）峰值。
- 持久化延迟和失败。
- 最终是否 degraded。
- 录音总时长、音频文件大小、峰值内存和平均 CPU。

日志不得写入完整用户语音正文；正文只进入用户会话文件。

## 14. 测试与验收

### 14.1 纯逻辑测试

- VAD 停顿在 10–18 秒之间产生候选边界。
- 无停顿在 18 秒产生硬边界。
- 跨边界窗口把候选边界放在中心安全区。
- 时间戳对齐、词元退回和字符退回分别通过。
- 第一次实质冲突后不继续确认。
- 已确认前缀在任何后续事件中都不可改变。
- 相同显示文本不发布新 revision。
- stale callback 不改变状态。
- 低置信度产生恢复计划而不是强制拼接。

### 14.2 调度测试

- 多个 fast 请求只执行最新一个。
- 边界任务不被 fast 请求覆盖。
- 停止时尾部任务优先。
- timeout 不被误报为 cancelled。
- session/epoch 切换后旧结果全部丢弃。
- 积压时暂停快速预览但不丢边界任务。

### 14.3 持久化与恢复测试

- 确认片段只追加并可重放得到相同正文。
- 写入中断不会破坏此前确认片段。
- 未完成会话可从最后确认时间恢复。
- 最终正文由确认片段与尾部严格按时间组装。

### 14.4 长时模拟测试

- 使用 deterministic fake provider（确定性假服务提供器）模拟至少 65 分钟音频事件。
- 验证状态内存不随全文字符数复制增长。
- 验证胶囊每次更新只处理有界最近上下文，不重复构造 65 分钟全文。
- 验证边界数量、持久化记录和最终组装完整。
- 模拟 ASR 慢于实时速度，验证积压和停止后追赶。
- 模拟中途失败、时间戳缺失、App 恢复和尾部降级。

### 14.5 真实安装版测试

1. 两个实验开关关闭，验证普通短口述与当前版本一致。
2. 只开重叠校正预览，录制包含停顿、连续长句、重复短语和中英文混合的 2–10 分钟样本。
3. 对比旧/新预览的首字延迟、跳变次数、接缝重复/缺字和 CPU。
4. 开启长录音模式，先完成 10 分钟验证，再执行至少 65 分钟真实录音。
5. 验证手动停止后不重跑整段录音，只完成积压边界与尾部。
6. 验证最终正文、完整音频、会话证据和 degraded 标记。
7. 验证智能整理、翻译或粘贴仍受现有安全保护。
8. 验证关闭实验设置后立即恢复旧路径。

UI 设置改动完成后必须执行 `design-review`（设计质量复核），并检查真实安装版设置层级、开关依赖、禁用状态和警示文案。

## 15. 发布、回退与毕业条件

### 15.1 发布方式

- 两个设置默认关闭。
- 首次只作为本地实验能力，不写成默认产品能力。
- 代码、日志和持久化格式都带实验版本号。

### 15.2 回退

- 关闭两个设置即恢复旧预览和完整录音 final ASR。
- 不删除旧代码，直到实验达到毕业条件并经过单独迁移决定。
- 实验会话文件与普通录音文件分开管理，回退不清理用户证据。

### 15.3 毕业条件

只有同时满足以下条件，才讨论默认启用或替代旧链路：

- 普通短口述首字延迟和最终准确率不退化。
- 接缝重复/缺字率达到明确基线目标。
- 65 分钟真实录音没有正文丢失、内存失控或无法收口。
- 停止时不执行整段 ASR，且尾部可稳定完成。
- 关闭开关可完整回退。
- 崩溃恢复、磁盘不足和输入设备断开经过验证。
- 文档、测试、构建安装和真实 App 复核全部完成。

## 16. 实施过程约束

- 采用 Strangler Migration（绞杀式迁移）：新模块旁路建立，开关选择，不在旧协调器内继续堆叠算法。
- 每个实现任务先写失败测试，再写最小实现，再运行测试。
- 每个任务必须明确修改文件、接口、验证命令、预期结果和回退点。
- 不需要等待整个实验功能全部完成才构建。每个具备独立运行与回退边界的 vertical slice（垂直功能切片）完成后，都允许并应执行相应的构建、覆盖安装和真实 App 验证。
- 任何代码改动完成后，按仓库规则更新 build（构建号）或完整版本、开发日志和版本历史。
- 构建前重新检查并发进程、dirty 文件和源码 mtime（修改时间）。
- 构建必须使用 `native/build_and_log.sh`，覆盖安装并验证真实 `/Applications/TypeWhale Pro.app`。
- 不以“编译通过”代替一小时场景、失败路径和回退验证。
