# TypeWhale 主麦克风选择与录音中热切换设计

## 1. 产品目标

TypeWhale 应允许用户在常用设置首屏选择 Mac 内建麦克风、AirPods、USB 麦克风或其他 CoreAudio 输入硬件作为主麦克风。界面选择必须与实际录音输入一致；用户在录音过程中改变主麦克风时，切换立即生效，同时保留同一轮录音、已录内容、实时预览上下文和最终文本任务。

本功能按可真实使用的产品能力设计，不以取消当前录音、要求用户重录或静默改用其他输入设备冒充“立即生效”。

## 2. 使用场景与当前问题

当前代码已经支持在录音开始前按设备 UID 绑定手动选择的输入设备，也在设置中提供了设备列表。但是入口位于较深的系统设置区域，产品语义不够突出；录音开始后无法按用户选择热切换设备，输入路由变化还可能取消当前录音。用户需要：

- 在常用设置首屏直接看到和选择“主麦克风”；
- 确认实际采集来自界面所选硬件；
- 在当前录音中切换设备并立即生效；
- 设备断开时安全切到跟随系统，且设备重连后不自动抢回；
- 不牺牲 ASR、VAD、实时预览、最终粘贴和已有录音内容。

## 3. 范围

### 3.1 In scope

- 枚举当前可用的 CoreAudio 输入硬件；
- 在常用设置首屏提供唯一的“主麦克风”选择入口；
- 持久化“跟随系统”或指定设备 UID；
- 录音开始时绑定所选设备；
- 当前录音中手动热切换主麦克风；
- 手动设备断开后永久切为“跟随系统”，并在当前录音中热切到系统默认输入；
- 输入格式归一化、切换状态、错误恢复、诊断和自动化测试；
- 构建、覆盖安装和真实硬件验证。

### 3.2 Out of scope

- 同时使用两个麦克风录制或混音；
- 为口述、闪念、OpenClaw 等不同功能分别指定不同麦克风；
- 持续监听或后台常驻采集；
- 自动评估哪个麦克风音质更好；
- 改变 ASR provider、VAD 算法、预览文本协议或最终粘贴语义。

### 3.3 Do not touch

- ASR 模型与模型内存治理规则；
- Silero VAD 的人声判断语义；
- 实时预览、长录音实验和最终 ASR 的权威文本边界；
- 快捷键激活、目标 App 捕获、智能整理、翻译和粘贴行为。

## 4. 产品交互

### 4.1 主入口

在主窗口常用设置首屏的录音相关区域新增“主麦克风”卡片。卡片包含：

- 当前选择的设备名称；
- 下拉列表，第一项为“跟随系统（当前系统默认设备名）”；
- 当前可用的其他输入硬件；
- 按需刷新设备列表的按钮；
- 简短状态副文案。

移除“更多设置 → 系统”里的重复设备选择入口，保证只有一个产品入口和一份权威状态。

设备枚举继续采用懒加载：只有打开列表、点击刷新、真正开始录音或录音路由需要处理时才访问 CoreAudio 设备列表，避免 App 空闲时长期进入系统麦克风模式。

### 4.2 状态反馈

卡片或录音胶囊按场景显示：

- “正在使用：设备名”；
- “正在切换麦克风…”；
- “已切换到：设备名”；
- “切换失败，继续使用：原设备名”；
- “设备名已断开，已改为跟随系统”；
- “系统输入不可用，录音已停止并保留已有内容”。

反馈不得抢占用户正在输入的目标 App 焦点。短状态应有稳定的最短展示时间，避免路由通知频繁到达时闪烁。

### 4.3 手动热切换

用户在录音过程中选择另一台主麦克风时：

1. 新选择立即持久化并发起热切换；
2. 当前录音保持同一个 task ID、胶囊、预览会话和最终输出任务；
3. 允许约 0.3–1 秒采集空档；
4. 切换前已经录入的音频和正文证据不得丢失；
5. 切换成功后当前录音从新设备继续采集；
6. 新设备绑定失败时优先恢复旧设备，并把选择回滚为旧设备。

### 4.4 设备断开

手动选择的设备一旦断开：

1. 立即清除该设备的持久选择，永久改为“跟随系统”；
2. 若当前正在录音，热切到当前系统默认输入并继续同一会话；
3. 明确提示“设备已断开，已改为跟随系统”；
4. 原设备重新连接后只刷新可选列表，不自动恢复、不自动抢切；
5. 用户必须再次手动选择，才能重新把它设为主麦克风。

App 启动或开始录音时若发现已保存的设备不存在，也执行同样的永久降级规则。

如果系统默认输入也不可用，录音应停止继续采集，但必须保留已经录入的音频并明确告知用户，不能继续显示虚假的“录音中”。

## 5. 技术架构

### 5.1 设备选择与解析

`AudioInputDeviceProvider` 继续负责设备枚举、UID 到当前 `AudioDeviceID` 的解析和系统默认设备查询，并补充明确的选择解析结果：

- 跟随系统且系统设备可用；
- 手动设备可用；
- 手动设备已断开并永久降级为跟随系统；
- 当前没有可用输入设备。

持久化层只保存产品选择，不把短生命周期的 `AudioDeviceID` 当作稳定身份。诊断可记录设备显示名和路由类型，但不得记录音频内容、转录正文或可用于跨机器识别用户的原始硬件标识。

### 5.2 单会话采集状态机

`AudioRecorder` 从“启动时绑定一次设备”升级为单一录音会话内可切换输入路由的状态机：

```text
idle → starting → recording → switching → recording → stopping → idle
                              ↘ failure recovery ↗
```

约束：

- `switching`、`stopping` 和 `cancel` 必须在同一串行控制队列上互斥；
- 快速连续选择多个设备时只让最新意图成为最终路由，过期切换结果不得覆盖新选择；
- 每个切换操作携带 generation/token，异步配置变化回调只处理当前 generation；
- 任一时刻输入节点只能安装一个有效 tap；
- 路由切换不得重置 task ID、录音开始时间、VAD 会话、实时预览权威状态或已写入帧数；
- 停止发生在切换过程中时，必须收口当前可用音频并只完成一次停止。

### 5.3 固定内部音频格式

不同输入硬件可能提供不同采样率、声道数或交错格式。录音会话使用固定、适合现有 ASR/VAD 的标准 PCM 格式作为内部权威格式；每个硬件输入先通过 `AVAudioConverter` 转换，再进入：

- 权威 WAV 写入；
- 波形和输入电平；
- Silero VAD 窗口；
- 实时预览快照；
- 长录音实验的音频边界。

切换新设备时根据其原生格式创建新的转换器，但权威写入文件格式和下游缓冲格式不变。转换器必须正确处理输入消耗、输出容量和尾部帧，不允许把不同格式的原始 buffer 直接写入同一个 WAV。

内部标准格式的具体采样率、声道和样本格式应以当前 ASR/VAD 入口需求及现有录音兼容性为准，在实施计划中通过代码与测试确认，不能凭假设硬编码。

### 5.4 热切换顺序

手动热切换使用以下顺序：

1. 进入 `switching` 并停止接受旧 tap 的新 buffer；
2. 排空已经接受的旧输入处理任务，保证已录内容写入完成；
3. 卸载旧 tap，停止并重置需要重建的输入引擎状态；
4. 绑定目标设备，读取有效输入格式并建立转换器；
5. 安装唯一的新 tap，启动引擎；
6. 收到或确认新输入链路有效后回到 `recording`；
7. 发布成功状态并更新当前路由快照。

切换期间 UI 保持当前录音会话，不新建第二个录音任务。

### 5.5 失败恢复

- 目标设备绑定或启动失败：尝试按相同流程恢复旧设备；恢复成功后回滚设置和 UI。
- 手动设备断开：先永久切换设置为“跟随系统”，再绑定当前系统默认输入；不回滚到已断开的设备。
- 旧设备和目标设备都不可用：尝试系统默认输入。
- 所有输入都不可用：停止采集并保存已录音频，终止依赖后续音频的预览/VAD 请求，向协调器返回明确错误。
- 切换失败不得删除已写入的 pending WAV；停止收口失败也必须保留可恢复证据。

## 6. 路由监听与生命周期

CoreAudio 设备列表和系统默认设备监听仅在以下场景启用：

- 当前正在录音；
- 主麦克风选择器正在展示或刷新。

空闲且设置 UI 不需要设备状态时停止监听。录音停止或取消后继续执行现有输入 tap、`AVAudioEngine` 和路由监听释放，不能引入空闲麦克风占用回归。

同一设备在蓝牙启动阶段产生的短暂 `AVAudioEngineConfigurationChange` 仍应沿用现有可恢复保护；只有设备 UID 确认消失或用户选择发生变化时，才进入真正的设备切换状态机。

## 7. 可观测性

增加不含正文和音频路径的诊断事件：

- 切换发起原因：用户选择、手动设备断开、系统默认变化、启动时解析；
- 原路由与目标路由的显示名或类别；
- 切换 generation、耗时、结果；
- 目标设备格式和内部标准格式的非敏感摘要；
- 是否恢复旧设备、是否降级跟随系统、是否因无输入停止；
- 切换空档估算和转换错误。

诊断用于区分“UI 已选择但未绑定”“设备绑定成功但无音频帧”“转换失败”“路由通知竞态”等问题。

## 8. 验收标准

### 8.1 用户可见验收

1. 常用设置首屏能直接查看并更改主麦克风；旧系统设置入口不再重复出现。
2. 选择 USB Mic、AirPods 或内建 Mic 后，下一次录音实际来自所选设备。
3. 录音中切换设备时，当前胶囊和录音会话不中断；允许约 0.3–1 秒空档，但切换前内容不丢失。
4. 切换结束后的音频实际来自新设备，UI 与真实输入源一致。
5. 手动设备断开后立即变为跟随系统；当前录音切到系统默认输入并继续。
6. 已断开设备重连后继续跟随系统，不自动抢回。
7. 新设备切换失败时继续使用原设备并回滚选择；若没有任何输入可用，则保留已有内容并明确停止。
8. App 重启后保留有效手动选择；若该设备已不存在，则永久改为跟随系统。
9. 切换不能破坏实时预览、VAD 自动完成、最终 ASR、智能处理或粘贴。
10. App 空闲时不因设备选择功能长期占用麦克风。

### 8.2 失败判定

以下任一情况发生即不算完成：

- 当前录音因正常手动切换被取消或要求用户重录；
- 切换前音频或最终文本丢失；
- UI 显示设备与真实采集来源不一致；
- 不同硬件格式导致 WAV 损坏、崩溃或 ASR 无法读取；
- 手动设备断开后仍保留失效选择；
- 设备重连后自动抢回；
- 快速切换导致重复 tap、重复停止或陈旧回调覆盖最新选择；
- 空闲状态持续占用麦克风或破坏现有蓝牙启动保护。

## 9. 测试方案

### 9.1 自动化与纯逻辑测试

- 选择解析：跟随系统、有效手动设备、失效手动设备、无系统设备；
- 持久化：有效选择保留，设备断开永久清为跟随系统，重连不自动恢复；
- 状态机：正常切换、目标失败恢复旧设备、断开后降级、所有输入失败、切换中停止；
- generation：连续选择 A→B→C 后只有 C 能成为最终路由；
- route change：同设备启动抖动不触发切换，设备 UID 消失才触发断开规则；
- 格式转换：44.1/48 kHz、单/双声道等代表性输入转换到内部标准格式；
- WAV：切换前后写入同一合法文件，总帧数和时长在允许空档范围内正确；
- 下游连续性：VAD、预览和最终 ASR 接收同一标准格式且不重置 task ID。

### 9.2 竞态测试

- 录音中快速连续选择多个设备；
- 切换目标设备恰好断开；
- 切换期间用户停止或取消；
- 手动设备断开同时系统默认设备变化；
- 蓝牙设备启动阶段连续配置变化；
- 切换失败后立即再次选择其他设备。

### 9.3 真实安装版手动验证

代码改动后必须通过唯一构建入口构建、覆盖安装到 `/Applications/TypeWhale.app`、打开安装版并校验签名。至少使用两台真实输入硬件：

1. 分别选择内建 Mic 与第二台硬件录制，通过物理静音、距离或输入电平确认真实来源；
2. 在一句连续口述中途切换，确认同一胶囊继续、前后语音均进入最终文本；
3. 录音中拔掉手动设备，确认立即跟随系统且不丢失已录内容；
4. 重新插回设备，确认仍跟随系统；
5. 模拟目标绑定失败，确认恢复旧设备并回滚 UI；
6. 覆盖实时预览开启/关闭、停顿自动完成、长按录音和手动停止；
7. 结束录音后确认系统麦克风占用指示按现有规则释放。

若执行环境没有第二台真实硬件，自动测试或虚拟设备不能替代真实验收；交付说明必须明确列出未验证的硬件、蓝牙或采样格式风险。

## 10. UI 设计复核

本功能涉及常用设置首屏和录音胶囊反馈。实现完成后必须执行 `design-review`，覆盖：

- 主麦克风入口的可发现性与信息层级；
- 设备名称截断、列表刷新和失效状态；
- 切换中、成功、失败与断开的反馈节奏；
- 是否闪烁、抢焦点、丢失录音上下文；
- 安装版真实录音中的视觉状态与实际输入是否一致。

## 11. 回退策略

- UI 回退：可恢复旧设置布局，但设备选择存储键保持兼容；
- 采集回退：热切换能力若出现不可接受的格式或稳定性问题，应通过明确的功能边界回退到“下次录音生效”，不能静默取消当前录音；此产品语义变化必须重新获得用户批准；
- 数据保护：任何回退都不得删除已经录入的 pending WAV 或改变 ASR/VAD/粘贴权威链路。
