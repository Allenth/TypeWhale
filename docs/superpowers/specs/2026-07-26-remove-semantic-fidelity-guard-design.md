# 删除智能整理语义保真检查

## 目标

TypeWhale 不再判断模型整理结果在内容上是否“足够忠实”。只要所选模型成功返回非空文本，App 就直接交付，由用户本人判断整理质量。

## 当前问题

`RewriteFidelityGuard` 会逐字检查英文术语、数字、限制词、疑问信号和文本重合度。它无法理解“不能”和“不得”等语义等价表达，会把正确的整理结果误判为 `missingConstraint`，随后由 `SmartInputRouter` 静默改为粘贴原文。

固定录音实测中，本地 Qwen3 4B 已生成整理结果，但因为原文的“先不要 / 不要 / 不能”被改写为“先不 / 不得 / 不得”，保真检查拒绝结果，导致用户看到未经整理的连续文本。

## 设计决定

- 完整删除语义保真检查：
  - 英文术语是否原样保留；
  - 数字是否原样保留；
  - 限制词是否逐字保留；
  - 疑问信号是否原样保留；
  - 输出与原文的字符重合度。
- 模型返回非空文本时直接交付，不再产生 `rewrite_fidelity_rejected`，也不再因内容判断回退原文。
- 删除 `RewriteFidelityGuard` 及其专属测试。
- 自动回放必须覆盖最终交付判断，防止未来重新加入同类内容拦截。

## 保留边界

以下属于技术有效性检查，不在删除范围内：

- 模型报错、超时或通信协议异常；
- 模型返回空文本；
- 本地模型输出中的控制标记和格式清理；
- 失败时不切换到其他模型；
- ASR、术语归一化、提示词、模型选择和粘贴流程。

## 数据流

调整前：

`ASR → 术语归一化 → 模型整理 → 语义保真检查 → 通过则交付 / 拒绝则粘贴原文`

调整后：

`ASR → 术语归一化 → 模型整理 → 非空结果直接交付`

技术错误和空结果继续进入现有失败处理，不调用其他模型。

## 验收标准

1. 原文含“不能”，模型输出使用“不得”时，整理结果可以直接交付。
2. 非空模型输出不会因为缺少某个英文词、数字、限制词、疑问词或字符重合度不足而回退原文。
3. 运行日志不再出现 `rewrite_fidelity_rejected`。
4. 模型报错、超时和空结果的现有技术异常处理保持不变。
5. Qwen3-ASR、Qwen3 4B、DeepSeek、提示词、失败不降级和粘贴行为不发生额外变化。

## 不做事项

- 不调整提示词。
- 不增加“保真检查”开关。
- 不增加新的内容评分、警告或二次模型复核。
- 不修改 ASR 专有名词识别策略。
