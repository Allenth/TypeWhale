# TypeWhale 本地 TTS 朗读测试设计

日期：2026-07-27
状态：已获产品确认，待实施计划

## 1. 背景与目标

TypeWhale 当前通过 Sherpa VITS Melo 模型朗读 OpenClaw 最终回复。本机还保存了多套未接入或散落在实验目录、模型缓存中的本地 TTS 资产。产品需要在「声音」页面增加独立的「朗读测试」section，让用户能够：

1. 输入或粘贴一段文字；
2. 选择已经通过本机验证的本地 TTS 模型；
3. 点击播放后听到该模型朗读输入文字；
4. 停止正在进行的生成或播放；
5. 直接比较首声等待、生成速度、实时率、内存和主观音质。

本轮同时把 Reader Demo 之外的可用 TTS 模型统一迁移到 TypeWhale 的模型目录，补充网络调研得到的第一、第二梯队候选，并清除经验证的重复残留。

## 2. 产品边界

### 2.1 In scope

- 在「声音」页增加与「小龙虾声音」并列的独立「朗读测试」卡片。
- 提供多行文本输入、模型选择、播放/停止、最近音频重播、状态和性能指标。
- 建立独立 TTS 测试接口和按模型隔离的适配器。
- 统一管理 TypeWhale 本地 TTS 模型目录、清单、完整性和验证状态。
- 一次性将第一、第二梯队全部加入受控并发下载队列。
- 迁移本机已有且完整的项目外 TTS 资产。
- 对所有候选执行一致的冷启动、热启动、中文、中英混读、数字符号、长文本、取消和离线测试。
- 对目标文件完成哈希校验和朗读验证后，清理确认重复的源文件、下载包和缓存残留。
- 输出结构化性能日志并保留最近生成的试听音频。

### 2.2 Out of scope

- 本轮不把实验通过等同于 OpenClaw 正式朗读默认引擎切换。
- 不提供声音克隆录音、训练、微调或云端 TTS。
- 不引入 Fish Speech S2、IndexTTS2 或已经停止官方维护的 Supertonic 3。
- 不为不完整、无法取消、无法离线复现或许可证不适合产品化的模型提供 UI 入口。

### 2.3 Do not touch

- `~/Library/Application Support/Reader Demo/` 整棵目录及其模型。
- 现有 OpenClaw 朗读开关、引擎选择、音量、语速、播放内容和打断策略的持久化语义。
- ASR、VAD、截图、快捷键、翻译、保存、复制等非 TTS 主流程。
- 来源不明或无法确认属于重复 TTS 资产的文件。

## 3. 用户体验设计

### 3.1 页面结构

「声音」页保留现有「小龙虾声音」卡片，在其后增加「朗读测试」卡片。测试卡片包含：

- 多行文本框；
- 已验证模型下拉框；
- 主操作按钮，空闲时为「播放」，运行时为「停止」；
- 「重播最近音频」入口；
- 状态文字；
- 性能结果区域。

测试卡片拥有自己的状态和选项，不读写 OpenClaw 的引擎设置，也不改变 OpenClaw 的预热、打断和播放策略。

### 3.2 状态机

可观察状态依次为：

`空闲 → 准备模型 → 冷启动/热启动 → 正在生成 → 正在播放 → 完成`

任一步骤都可以进入「失败」或被用户「停止」。停止必须同时终止仍在进行的模型生成和音频播放，并释放本次测试占用的临时进程或任务。切换模型或开始新测试前必须结束上一任务，不允许多个模型在后台继续朗读。

### 3.3 性能展示

每次完成后直接在页面展示：

- 冷启动或热启动；
- 模型准备耗时；
- 开始出声等待时间；
- 总生成耗时；
- 生成音频时长；
- RTF（总生成耗时 / 音频时长）；
- 峰值内存；
- 完成、停止或失败状态。

同一结果写入结构化测试日志。最近生成的有效音频保留在 TypeWhale 测试输出目录，可重复播放，不需要重新推理。

### 3.4 文本行为

- 文本框提供一段覆盖中文、英文、数字和标点的默认示例。
- 用户修改后的文本持久化，下次打开仍然存在。
- 空文本不启动任务，并在原位置给出明确提示。
- 长文本按句子边界切分，模型支持流式时优先边生成边播放；不支持流式时生成完成后播放。

## 4. 架构设计

### 4.1 独立测试模块

新增独立于 `OpenClawVoicePlayer` 的朗读测试服务。它负责：

- 枚举已验证模型；
- 创建对应适配器；
- 驱动准备、生成、取消和回收；
- 采集时间、音频和内存指标；
- 向 UI 发布单一状态流；
- 写入测试结果。

现有 Sherpa 后端允许提取可复用的底层能力，但测试服务不得复用 OpenClaw 的活动队列或持久化设置。

### 4.2 适配器边界

每个模型适配器实现一致能力：

- `validate()`：验证文件、运行时和许可证清单；
- `prepare()`：加载或预热模型；
- `synthesize(text)`：生成完整或流式音频；
- `cancel()`：及时停止当前生成；
- `shutdown()`：释放测试专用资源；
- 能力声明：语言、流式、内置音色、风格控制和最低系统版本。

模型只有在 `validate`、有效音频生成、取消和离线复测全部通过后，才写入已验证状态并出现在下拉框中。

### 4.3 模型目录

统一根目录：

`~/Library/Application Support/TypeWhale Pro/Models/tts/`

每个模型使用独立子目录并包含 TypeWhale 清单，记录：

- 模型标识和展示名；
- 上游来源和版本；
- 文件格式和哈希；
- 代码及权重许可证；
- 运行时类型和版本；
- 下载/迁移完成状态；
- 本机验证状态；
- 最近性能结果。

临时下载写入 TypeWhale 专用 staging 目录。下载完成并校验后原子移入正式目录，避免 UI 看到半成品。

## 5. 模型矩阵

### 5.1 第一梯队

1. Sherpa VITS Melo：现有产品基准线。
2. Qwen3-TTS 0.6B Core ML：原生 Swift/Core ML、低延迟重点候选。
3. Qwen3-TTS 1.7B Core ML：更高质量和风格控制候选。
4. Kokoro INT8：小体积、低资源基线。
5. ZipVoice Distill INT8 + Vocos：中英双语候选，按组合模型包验证。

Qwen3 Core ML 优先采用 Argmax TTSKit 的原生路线。现有 PyTorch `safetensors` 与 Core ML 权重不重复保留：Core ML 路线完成真实验证且旧权重确认不再被任何适配器使用后，再删除旧副本。

### 5.2 第二梯队

1. Fun-CosyVoice 3.0：中文、方言、自然度和流式能力候选。
2. MOSS-TTS：长文本、表现力、克隆能力和显式停顿候选。
3. VoxCPM2：中文表现力和 Apple MPS 候选。

第二梯队与第一梯队一起下载，但仍先进入隔离 spike。只有满足与第一梯队相同的完整准入标准，才允许显示在正式下拉框。

### 5.3 明确排除

- Supertonic 3：上游已宣布归档并停止官方支持，长期产品依赖风险过高。
- Fish Speech S2：专用 Research License 不符合当前商业主线的清晰授权要求。
- IndexTTS2：模型许可证含商业规模和用途限制。
- 不完整的 Spark-TTS、Piper、Qwen3 MLX 等占位缓存：不视为可迁移模型。

## 6. 下载、迁移与清理

### 6.1 下载

- 所有第一、第二梯队候选一次性加入队列。
- 最大并发下载数为 3，避免八个大模型无限并发抢占网络和磁盘。
- 支持断点续传、已完成文件复用和逐模型失败隔离。
- 本轮模型资产预算上限为 50 GB。
- 任何时候至少保留 15 GB 系统空闲空间。
- 达到任一限制后停止新下载和未落盘的大文件，不删除已经校验成功的模型。

### 6.2 本地迁移

Reader Demo 之外的完整本地资产采用：

`复制到 staging → 计算源/目标哈希 → 原子移入正式目录 → 朗读验证 → 清理源文件`

首批迁移对象包括：

- LocalTTSLab 的 Kokoro INT8；
- LocalTTSLab 的 ZipVoice Distill INT8；
- 与 ZipVoice 配套的 Vocos；
- TypeWhale 目录内现有 Qwen3 权重，先记录并判断是否能被最终运行时复用。

### 6.3 残留清理

只有同时满足以下条件才允许删除源文件：

1. 目标模型文件完整；
2. 源/目标哈希一致；
3. 目标模型完成真实朗读；
4. 目标模型完成取消验证；
5. 已确认没有保留中的工具继续依赖源路径。

可清理范围包括确认重复的源模型、下载压缩包、失败任务临时目录和空的模型缓存引用。Reader Demo、非 TTS 资源和来源不明文件始终排除。删除后记录精确路径、释放空间和是否可恢复。

## 7. 错误处理

- 单模型下载、校验、运行时或推理失败不影响其他模型。
- 错误信息必须指明阶段、模型和可操作原因，不能只显示“播放失败”。
- 下载失败保留可安全续传的部分文件；不支持续传或校验失败的临时文件自动清理。
- 推理超时、崩溃或取消后必须清除活动进程、音频播放器和临时输出。
- 已验证模型的新版本验证失败时，保留最后一个可工作的版本。
- OpenClaw 正式朗读不得因测试模型失败而停止、改设置或丢失预热状态。

## 8. 验收与测试

### 8.1 单模型准入

每个候选必须满足：

1. 文件和许可证清单完整；
2. 生成有效且可播放的 WAV；
3. 中文、中英混读、数字和符号没有明显漏读、截断或乱码；
4. 长文本完整结束；
5. 生成和播放都可以取消；
6. 连续运行三次不崩溃；
7. 冷启动和热启动指标可重复采集；
8. 峰值内存可记录且不导致系统明显失去响应；
9. 断网后可以再次完成相同朗读。

### 8.2 统一测试语料

- 短中文；
- 中英混读和技术词；
- 日期、金额、百分比、网址和标点；
- 多句长段落；
- 空文本和超长文本边界；
- 播放中停止、生成中停止和快速切换模型。

### 8.3 UI 验收

- 「声音」页能看到独立「朗读测试」卡片。
- 输入文字、选择模型、点击播放后状态按真实阶段变化。
- 播放按钮运行时变为停止，停止反馈及时且无残留声音。
- 页面直接显示首声、总耗时、音频时长、RTF、峰值内存和冷/热状态。
- 失败信息不挤坏布局，长文本和窗口缩放不造成控件跳变。
- OpenClaw 原设置和自动朗读行为保持不变。

### 8.4 质量复核与交付

- UI 完成后执行独立 `design-review`，覆盖视觉层级、节奏、状态切换、停止反馈、长文本和失败状态。
- 执行相关自动化测试和模型隔离测试。
- 递增 build 号并通过唯一入口构建。
- 覆盖安装并打开 `/Applications/TypeWhale Pro.app`。
- 在真实安装版完成视觉、播放、停止、失败和 OpenClaw 回归验证。
- 更新开发日志、必要的架构说明和版本历史。
- 复核 git 范围并提交该 build 对应改动。

## 9. 成功标准

本功能成功不是“模型能被列出来”，而是用户能在真实安装版中稳定完成：

`输入文字 → 选择已验证模型 → 播放/停止 → 听到完整内容 → 看懂性能差异`

同时，Reader Demo 与 OpenClaw 主流程保持完整，模型目录无半成品和已确认重复的残留文件，所有显示的模型都能在断网环境下重复朗读。
