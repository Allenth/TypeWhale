# 智能整理通用语义结构规则

日期：2026-07-26

## 目标

无论用户选择本地 Qwen3 还是在线 DeepSeek，也无论使用哪一种智能整理模式，模型都应先理解一句话中不同内容的作用，再用清晰的标点、分句或换行组织结果。

固定验收输入：

> 响应速度不能改为影响速度。测试包含 Gpt chatgpt12345 和今天真的可以吗？

目标输出结构：

> 测试内容包括：GPT、ChatGPT、12345，以及“今天真的可以吗？”。
> 注意：“响应速度”不能改成“影响速度”。

实际措辞可以随整理模式略有不同，但“测试内容”和“注意事项”不得继续挤在同一句中。

## 设计决定

在 `SmartRewritePromptBuilder` 的公共提示词契约中增加语义结构规则，由所有会执行智能整理的模式共同继承。该契约放在原始语音文本之后，作为模型生成前最后读取的统一输出规则，避免被模式模板或原文顺序覆盖：

1. 先判断同一段话中是否包含要求、测试内容、疑问、限制、步骤等不同语义。
2. 不同语义应使用自然分句、换行或列表区分，不得为了简短强行拼成一句。
3. 只有原文存在明确分类时才组织结构，不强制给所有短句添加标题或固定模板。
4. 保留数字、专有名词、否定关系和疑问语气；结构整理不能改变这些内容的关系。
5. 只要求模型按规则输出，不增加 App 侧语义保真、评分、拒绝或回退判断。

各模式原有职责保持不变：

- 聊天模式仍输出自然聊天文本，不强制标题或项目符号。
- 润色模式仍以轻量改善为主。
- 开发需求模式仍保留第一人称、反馈、限制和步骤。
- 极致归纳仍允许压缩，但必须区分不同语义。

## 模型与数据流

本地 Qwen3 和在线 DeepSeek 继续使用同一个 `SmartRewritePromptBuilder`：

`全局与模式边界 → 原始识别文本 → 公共语义结构契约 → 当前选中的整理模型 → 直接交付`

本轮不新增模型专属提示词，也不改变模型选择和失败处理。

## 自动化测试

1. 在提示词契约测试中加入固定验收输入。
2. 检查每个可编辑整理模式都包含通用语义结构规则。
3. 检查规则明确要求区分“要求、测试内容、疑问、限制、步骤”等语义，并允许分句、换行或列表。
4. 检查规则禁止把不同语义强行拼成一句，同时不要求所有短句套固定标题。
5. 运行现有提示词契约测试，确认各模式既有规则不回退。
6. 使用本地 Qwen3 对固定输入进行真实回放，并向用户展示实际结果。

DeepSeek 与本地模型共用同一提示词构建结果，因此契约覆盖由自动化测试验证；若没有可安全使用的在线 Key，本轮不发送付费请求。

## 验收标准

- 所有智能整理模式均继承同一条语义结构规则。
- 固定输入的模型结果能清楚区分“测试内容”和“注意事项”。
- `GPT`、`ChatGPT`、`12345`、“响应速度 / 影响速度”以及疑问语气得到保留。
- 不恢复或新增任何 App 侧语义保真检查。
- ASR、模型选择、失败不降级、粘贴、UI 和自定义模板保存逻辑保持不变。

## 不在本轮范围

- 修改语音识别结果。
- 调整专有名词词库。
- 新增 UI 设置或单独开关。
- 修改模型运行时、下载、内存和预热策略。
- 恢复语义保真检查或由 App 判断整理结果是否正确。

## Build 841 修正

Build 840 的具体校准示例会被 Qwen3 4B 复制到无关短句中，因此具体测试答案不再进入生产提示词。公共结构规则只保留泛化边界。

Qwen3 4B 在精简提示词下仍可能把“你要确保他成功”改为“我要确保他成功”，说明短句保真不能依赖模型服从。极致归纳遇到真正简单的单句时改为直接交付术语归一化后的识别文本，不调用整理模型；复杂内容继续使用当前选择的模型。本策略是调用前的确定性路由，不对模型结果评分、拒绝或回退，不恢复语义保真检查。
