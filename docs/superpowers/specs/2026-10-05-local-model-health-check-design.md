# TypeWhale 本地整理模型一键检测设计

日期：2026-10-05

状态：产品范围已确认，待实施

基线：TypeWhale Pro 2.0.58 (Build 915)

## 1. 产品目标

在主窗口“模型”页增加一个随时可用的本地整理模型检测入口。用户怀疑智能整理失效时，不需要打开终端或阅读日志，只需点击一次，就能确认故障发生在运行环境、模型文件、模型加载还是最小生成，并复制不含用户正文的诊断信息。

本功能必须验证真实生成链路，不能再次把“文件存在”“依赖版本号存在”或 Worker 进程存在误报为模型正常。

## 2. 用户场景与当前痛点

2026-10-05 现场证据显示：当前仍选择本地 Qwen3 4B，模型目录和 Worker 进程均存在，但 macOS 27.0.1 无法加载旧 SciPy 动态库，`mlx_lm` 在导入阶段失败。现有运行时检查只读取包版本；预热收到 `ok=false` 后仍记录 `warmup_done`，正式整理再静默回退原文。用户看到的现象因此是“智能整理完全失效”，界面却没有可信说明。

预期使用方式：

1. 用户进入“模型”页，在“整理模型”区看到“本地模型检测”。
2. 点击“开始检测”，界面依次显示当前阶段，主窗口保持可操作。
3. 成功时显示模型可用、总耗时和关键生成指标。
4. 失败时显示大白话原因、失败阶段和建议动作；用户可复制脱敏诊断详情。
5. 检测不切换当前模型、不修改模型或运行时、不调用云端服务。

## 3. 范围边界

### In scope

- 在“模型”页现有“整理模型”卡片内增加本地模型检测区。
- 检查 TypeWhale 受管 Qwen3 4B，不受当前下拉选择为本地或 DeepSeek 的影响。
- 顺序执行运行环境真实导入、模型资产完整性、模型预热、最小生成。
- 将检查状态建模为未检测、检测中、成功、失败；检测中展示具体阶段。
- 成功结果包含总耗时，并在可用时包含加载耗时、首 token 耗时、生成耗时和内存峰值。
- 失败结果包含用户可读结论、失败阶段、稳定错误码和脱敏技术详情。
- 提供“复制诊断”按钮；复制内容只包含 App/系统版本、模型 ID、阶段、错误码、耗时和技术错误，不包含录音、识别文本、提示词、API Key 或路径外的个人数据。
- 修正本地 LLM 预热对 `response.ok` 的判断，禁止把失败响应记录为成功。
- 将 LLM 运行时健康检查从“只核对包版本”提升为真实 `import mlx_lm`，并保留明确错误原因供检测界面使用。
- 增加自动化测试、现行产品/架构/设计/开发日志记录和应用内版本历史。

### Out of scope

- 不提供一键下载、重装、升级或修复运行环境。
- 不删除或替换模型文件、Python、SciPy 或其他依赖。
- 不检测 DeepSeek Key、余额、网络或云端模型。
- 不建立常驻轮询、自动弹窗或每次录音前强制检测。
- 不新增模型性能排行榜或长文本质量测试。

### Do not touch

- 不切换用户当前整理模型和整理模式。
- 不修改 ASR、VAD、录音、翻译、截图、粘贴、自动发送和遥控器行为。
- 不静默调用 DeepSeek 或其他云端服务作为检测 fallback。
- 不记录或复制用户正文、提示词、录音路径和密钥。
- 检测本身不得覆盖剪贴板；只有用户明确点击“复制诊断”时才写入脱敏诊断。
- 检测失败不得主动停止或删除当前受管 Worker；正式输入链路继续按现有原文安全回退。

## 4. 方案选择

### 采用：模型页内联检测区

在现有“整理模型”卡片中，下拉框和说明文字之后增加一条原生检测区：状态文案、主按钮和“复制诊断”次按钮。检测详情使用最多三行的可换行文字，避免扩大主窗口信息噪音。

优点：入口与本地模型选择相邻，问题与操作位置一致；日常不抢主流程；成功、失败和复制动作都能在原页面完成。它复用现有 AppKit、系统字体、圆角按钮和主题色，不引入新窗口或新导航。

### 不采用：独立诊断弹窗

弹窗能容纳更多日志，但会把一次简单检查变成新的窗口流程，并与现有“测试日志”入口重复。对当前单模型诊断过重。

### 不采用：启动时后台自动检测

自动检测可提前发现问题，但会在每次启动加载约 3GB 模型，并可能把次级诊断变成启动性能和内存负担。本轮保留用户显式触发；现有选择后的预热仍按原生命周期运行。

## 5. 检测架构与数据流

新增一个与 AppKit 解耦的本地模型检测服务，输出稳定的阶段事件和最终报告：

```text
模型页“开始检测”
    → LocalModelHealthCheckService
        1. runtimeImport：真实执行 import mlx_lm
        2. modelIntegrity：ManagedLLMModelRegistry 完整校验
        3. modelWarmup：共享受管 Worker 预热并要求 response.ok == true
        4. minimalGeneration：发送固定、本地、无用户正文的最小生成请求
    → LocalModelHealthReport
        ├─ passed(metrics, diagnosticText)
        └─ failed(stage, code, userMessage, technicalDetail, diagnosticText)
    → MainViewController 状态投影
```

### 运行时导入

- 继续校验 `mlx-lm` 与 `transformers` 固定版本，但不能以包元数据作为最终健康结论。
- 使用受管 Python 真正执行 `import mlx_lm`；捕获退出码和有界 stderr。
- 将动态库无法加载、模块缺失、版本不匹配和 Python 不可执行区分为稳定错误码。
- 已知动态加载错误在主界面显示“运行环境与当前 macOS 不兼容”；完整但有界的底层错误只进入复制诊断。

### 模型完整性

- 复用 `ManagedLLMModelRegistry.readiness` 的目录边界、文件大小和 SHA-256 校验。
- 模型缺失、文件大小错误、哈希错误和路径逃逸分别保留现有安全语义。
- 完整哈希可在后台线程执行；不得阻塞主线程。

### 预热与最小生成

- 使用 `ManagedLLMRuntimeService.shared` 的受管 Worker，避免在健康状态下再加载一份约 3GB 的模型。
- 开始前检查共享运行时是否正处理正式整理、翻译或预热；繁忙时返回 `runtime_busy` 并提示稍后重试，不排队抢占、不取消用户任务。
- 运行时串行队列继续保证请求不并发破坏 Worker；检测按钮在本次任务结束前禁用，阻止重复点击。
- 预热和生成都必须检查协议版本、`cancelled`、`ok`、错误码和响应正文，任何 `ok=false` 都是失败。
- 最小生成只使用固定测试提示，不带用户历史或当前转录；要求返回非空、可解码文本。
- 检测只验证链路，不把测试输出写入最近转录、剪贴板或用量账本。

## 6. UI 与交互

### 布局

- 保留现有“整理模型”下拉和说明文字，不改变模型页其他区域。
- 在说明文字下新增“本地模型检测”行，右侧主按钮标题初始为“开始检测”。
- 行下方增加状态详情，初始为“尚未检测 · 点击后将实际加载模型并完成一次最小生成”。
- 失败或成功后显示“复制诊断”次按钮；检测前隐藏，检测中禁用。
- 使用现有 `rowStack`、`optionRow`、系统字体、主题色和圆角按钮；不新增第三方字体或图标素材。

### 状态

| 状态 | 主文案 | 按钮 | 视觉语义 |
| --- | --- | --- | --- |
| 未检测 | 尚未检测 | 开始检测 | 中性 |
| 检测运行环境 | 正在检查运行环境… | 检测中（禁用） | 处理中 |
| 校验模型 | 正在校验 Qwen3 4B 模型文件… | 检测中（禁用） | 处理中 |
| 预热 | 正在加载本地模型… | 检测中（禁用） | 处理中 |
| 最小生成 | 正在验证模型生成… | 检测中（禁用） | 处理中 |
| 成功 | 本地模型正常 · 可用于智能整理 | 再次检测 | 成功；同时显示总耗时 |
| 失败 | 本地模型不可用：具体原因 | 再次检测 | 错误；显示建议并提供复制诊断 |

状态不能只靠颜色表达；文案、可访问性值和按钮状态必须同步。长错误允许换行，不挤压下拉框，不截断相邻控件。按钮的 accessibility label 分别为“检测本地整理模型”和“复制本地模型诊断”。

## 7. 错误与可观测性

- 最终报告使用稳定阶段和错误码，例如 `runtime_busy`、`runtime_python_missing`、`runtime_import_failed`、`model_missing`、`model_integrity_failed`、`warmup_rejected`、`generation_rejected`、`generation_empty`。
- `LaunchDiagnostics` 记录检测开始、阶段、完成或失败、模型 ID、耗时、错误码和安全错误类型；不记录固定测试提示全文或生成正文。
- 现有后台预热必须在 `response.ok == false` 时记录 `warmup_failed`，不能再产生指标全为 `-1` 的 `warmup_done`。
- 正式整理失败仍保留原文，但本检测功能让用户能主动得到明确根因；本轮不改变正式输入的提示层级。

## 8. 测试策略

### TDD 自动化

- 服务阶段顺序：运行时导入 → 模型完整性 → 预热 → 最小生成。
- 任一阶段失败时停止后续阶段，并输出对应稳定错误码。
- `response.ok=false` 的预热和生成都必须失败；不能只因进程未崩溃而通过。
- 最小生成成功但正文为空时失败。
- 运行时探针真实导入 `mlx_lm`，不允许只读包版本。
- 同一时间只运行一个检测任务；重复点击不会创建第二次请求。
- 诊断文本不包含测试提示正文、生成正文、用户转录或 Key。
- UI 源码边界覆盖按钮、状态、复制动作、可访问性标签及模型页接线。
- 原有模型路由、Worker 协议、生命周期、智能整理提示词和设置回归继续通过。

### 真实安装版

1. 打开“模型”页，确认检测区与模型下拉同卡片、无遮挡且无需横向滚动。
2. 在当前已知不兼容运行环境上点击检测，确认主窗口可操作，最终明确显示“运行环境与当前 macOS 不兼容”，而不是“正常”或空白失败。
3. 点击“复制诊断”，核对包含 App/系统版本、阶段和错误详情，不含最近转录、提示词或密钥。
4. 在修复后的兼容运行环境上再次检测，确认完成真实最小生成并显示成功及耗时。
5. 检测前后核对当前整理模型、整理模式、自动翻译状态和最近转录均未改变。
6. 深色与晨雾浅色主题各检查一次；核对长错误换行、按钮禁用、键盘焦点和 VoiceOver 标签。

## 9. 可观察验收标准

- 用户能在模型页一键判断本地 Qwen 是否真实可生成，而不是仅判断文件或进程存在。
- 当前 macOS 27.0.1/SciPy 动态库故障被准确判为运行环境失败，并给出可复制详情。
- 失败响应不会再被预热日志或 UI 误报为成功。
- 检测异步执行，主窗口不冻结；同次检测没有重复 Worker 请求。
- 检测不切换模型、不调用云端、不修改或删除本地文件、不污染最近转录和剪贴板。
- 安装版深浅主题、长错误、成功、失败和重复检测状态均完成设计复核。

## 10. 回退

代码回退时删除模型页检测区和独立检测服务即可；现有模型选择、正式整理路由和受管 Worker 协议保持兼容。若新检测服务异常，不能影响正式输入链路，最坏情况只应是检测按钮报告失败。
