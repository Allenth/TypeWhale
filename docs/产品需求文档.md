# TypeWhale 产品需求文档（PRD）

最后更新：2026-07-24
当前本地安装版基线：TypeWhale Pro 2.0.58 (Build 837)
文档性质：产品级需求、边界、验收与路线图；不是开发日志，也不是逐条 changelog。

## 1. 产品定义

TypeWhale 是一个本地优先的桌面语音输入与智能文字处理工具。它让用户在任何当前工作流中，通过全局快捷键完成“说话 -> 本地识别 -> 可选智能整理/翻译 -> 自动写回目标应用”的输入链路，并通过一个不抢焦点的录音胶囊提供实时确定感。

TypeWhale 的核心不是“语音转文字 demo”，而是一个可长期后台运行、可商业化分发、能进入用户真实工作流的 macOS 输入生产力工具。

一句话价值：

> 让高频桌面用户用语音稳定、低打扰、可控地完成原本需要键盘输入、复制、整理和翻译的文字工作。

## 3. 产品原则

### 3.1 本地优先

默认语音识别在本机完成。音频、识别文本、剪贴板内容和目标应用上下文都属于敏感数据。任何新增网络发送能力都必须在代码、UI 和文档中显式说明。

当前允许的远程能力：

- DeepSeek 智能整理。
- DeepSeek 自动翻译。
- DeepSeek 截图翻译。

当前默认智能整理、自动翻译和截图翻译优先走本机 Ollama；只有用户选择 DeepSeek 并配置 API Key 后，对应文本才发送给 DeepSeek。无论使用本地 Ollama 还是 DeepSeek，这些能力都必须是用户可理解、可配置、失败可回退的增强层，不能成为本地输入主链路的硬依赖。

### 3.2 输入链路优先

语音输入主链路的成功标准高于功能丰富度：

```text
全局快捷键 -> 录音 -> 胶囊反馈 -> final 本地识别 -> 粘贴回目标应用
```

任何新功能都不能破坏：

- 快捷键响应。
- 录音稳定。
- 胶囊确定感。
- final 识别质量。
- 目标应用粘贴正确性。
- 剪贴板恢复。
- 已开始的后台识别、整理、归档或保存任务。

### 3.3 胶囊是信心锚点，不是装饰

录音胶囊的作用是让用户在说话时确认“应用正在听、正在理解、没有失控”。它必须安静、快速、稳定、不抢焦点。

胶囊实时预览不是最终文本来源。最终粘贴必须来自完整录音的 final ASR。

### 3.4 已验证好体验不能被“修 bug”顺手砍掉

历史上 1.2 胶囊体验被用户确认更好。后续所有胶囊、预览、动效、停顿、分块、VAD 改动，都必须尊重这个事实：

- 自然停顿不能让预览窗口重置。
- 已显示的稳定前缀不能反复跳变。
- 不能为了避免闪烁而删除运动连续性。
- 不能为了性能退回上下文断裂的短窗口识别。

### 3.5 后台运行必须低打扰、可恢复

TypeWhale 是状态栏常驻工具，不是每次使用后退出的单次工具。它必须处理长期后台、睡眠唤醒、权限变化、模型内存增长和目标应用变化。

内存治理的产品目标是“持续响应快，同时避免异常膨胀”，不是“尽可能省内存”。ASR/VAD 模型不应在每次输入后卸载，也不应因空闲定时卸载导致下一次开口卡顿。高内存安全网使用动态预警阈值：`min(20GB, max(2GB, 本机物理内存 * 25%))`，避免回到 1GB 附近频繁 flush/reload。

### 3.6 截图是观察工具，不能改变桌面状态

进入截图模式不应唤醒 TypeWhale 主窗口，也不应改变普通 app 的 z-order。只有用户明确选择某个窗口截图时，才可以为了捕获目标窗口而临时置顶该窗口并重新截图。

截图也不应因为语音输入正在进行而被禁用。用户在录音、识别、整理或粘贴后处理期间触发截图时，截图覆盖层应正常出现，且不得停止、取消或改写当前语音会话。

### 3.7 智能处理是整理层，不是代答代理

智能整理、自动翻译和截图归档处理的对象是用户提供的素材与目标表达，不是让模型代替用户执行素材里的命令。原始语音里出现“回复用户、咨询、建议、安抚、引导、话术”等内容时，TypeWhale 仍应把它整理成用户要发出的需求、反馈或文本表达本身，不能直接生成给最终对象的建议或回复。

## 4. 目标用户与场景

### 4.1 高频文字输入用户

代表场景：

- 微信、飞书、邮件、备忘录、浏览器输入框中快速输入。
- 不想离开当前上下文打开独立转写工具。
- 希望录完后文本直接出现在原输入位置。

核心诉求：

- 快捷键一按就能说。
- 不打断当前应用。
- 粘贴目标准确。
- 识别失败时结果不丢。

### 4.2 产品负责人 / 开发者 / AI 协作用户

代表场景：

- 口述开发需求、bug 反馈、复盘和任务拆解。
- 在 IDE、Codex、Obsidian、聊天工具之间频繁切换。
- 需要把口语整理成更适合执行的需求或行动项。
- 看到页面、报错、竞品或聊天内容后，需要一键截图 OCR、归档为 Markdown 并保留原图附件。
- 突然想到一个产品判断或实现方向时，希望不粘贴到当前 App，而是用闪念胶囊单独保存。

核心诉求：

- 保留原始语义、约束和情绪强度。
- 自动识别开发场景并选择开发需求整理。
- 不把用户口述内容误当成给模型的新指令。
- 最近转录和需求池能兜住失败或后续整理。
- 截图归档和闪念胶囊要进入 Obsidian 需求池，带可追溯原文、模式和附件。

### 4.3 双语沟通用户

代表场景：

- 中文口述，自动转成自然英文聊天/工作表达。
- 中文口述，强制生成带语义 emoji 的英文聊天表达。
- 英文内容截图后翻译成中文并保留在图片中。
- 需要区分“润色”和“翻译”，避免智能整理擅自改变语言。

核心诉求：

- 翻译开关独立。
- 翻译方向明确。
- 译文自然，不机械。
- 社交聊天能更像真实 texting English，emoji 贴近对应词而不是堆在句尾。
- 成本和失败状态可见。

### 4.4 长时间后台使用用户

代表场景：

- TypeWhale 一直开着，白天断续使用。
- 电脑睡眠、唤醒、接入蓝牙耳机、通话软件切换输入设备。
- 期望它像输入法一样稳定，而不是像实验脚本一样需要重启。

核心诉求：

- 空闲不发热。
- 下一次开口不冷启动。
- 睡眠唤醒后快捷键恢复。
- 权限和模型状态可诊断。

### 4.5 Windows 平台潜在用户

Windows 版当前不是 macOS 完整能力的同级产品，而是平台扩展 MVP。

第一阶段目标：

```text
全局快捷键录音 -> Silero VAD -> SenseVoice final 本地识别 -> Ctrl+V 粘贴
```

非第一阶段目标：

- macOS 胶囊完整动效。
- 实时预览。
- 截图翻译。
- 智能整理。
- 托盘、安装包和签名之外的商业化完整体验。

## 5. 产品范围

### 5.1 当前主线能力

P0 当前能力：

- macOS 原生 App。
- 状态栏常驻入口。
- 全局录音快捷键。
- 单击切换录音、长按说话。
- 非激活录音胶囊。
- 本地 SenseVoice / sherpa-onnx final ASR。
- Silero VAD 人声判定。
- 自动粘贴到目标应用。
- 剪贴板恢复和粘贴前就绪闸门。
- 最近转录历史。
- 权限、模型、热键和运行状态诊断。
- 录音入口切换和后台语音任务保护：新入口可以立即开始，旧录音继续识别、整理或保存，不因新会话开始而丢弃。

P1 当前能力：

- 胶囊实时预览。
- 胶囊 dBFS 输入电平。
- 停顿自动完成。
- 录音时降低系统音量。
- 智能整理。
- 自动翻译。
- 中译英、多表情聊天中译英、英译中三类翻译方向。
- 社交窗口自动中译英聊天模板。
- 闪念胶囊：独立快捷键、独立整理模式、默认即时归纳、保存 Markdown 且不自动粘贴。
- 自定义提示词、开发术语和自动规则。
- 智能 Tab 集中管理整理模式、闪念整理、归档整理、翻译方向、整理模型、自动范围、提示词、开发术语、社交清单和 DeepSeek Key / 余额。
- 本地 Ollama / DeepSeek 整理模型选择、成本统计和余额展示。
- 模型管理面板：候选 ASR / VAD / 标点模型下载、下载进度、停止、覆盖安装后的进度恢复和用户级持久目录。
- OpenClaw 语音对话实验入口：独立 OpenClaw Tab、默认未设置的用户自定义激活键、红色小龙虾胶囊、本机 Gateway 检测、回复左上角红色堆栈展示；该路径不自动粘贴到当前 App。
- 本地 TTS 语音合成实验：优先通过本机 sidecar 服务调用开源 TTS 模型；模型管理器作为可选增强，不进入主输入链路默认依赖。

P2 当前能力：

- 截图选区、窗口候选、标注、撤销/前进、OCR、复制和保存。
- 英文截图翻译为中文。
- 行级 OCR 翻译回贴、去重、分块和动态超时。
- 截图马赛克（高斯模糊）标注。
- 截图 OCR 知识归档：Markdown、OCR 原文、同名截图附件和归档整理模式。
- 本地 Obsidian 需求池、闪念胶囊和截图归档目录。
- Windows WPF MVP 源码和交接计划。

### 5.2 当前非目标

当前不承诺：

- 作为系统输入法安装。
- 替代 macOS dictation。
- 完整离线智能整理。
- 云端语音识别。
- 自动上传音频或遥测。
- 公证后的正式公开商业分发包。
- Windows 与 macOS 完全同功能。
- 中英自动判断的截图双向翻译。
- 生成式图片背景修复。
- 托管 Ollama / LLM 大语言模型分发包。
- 把模型下载器中的 Pro ASR 候选模型静默接成默认识别主路。

### 5.3 已搁置或回滚方向

这些方向不应被后续 agent 当成“待恢复默认方案”：

- macOS 12 兼容：已放弃，当前基线为 macOS 14+。
- Python worker：已移除，当前为原生 sherpa-onnx / ONNX Runtime bridge。
- 每次输入后卸载 ASR/VAD：已否决，会破坏连续输入速度。
- 空闲 N 秒后卸载模型：已取消，下一次输入不能冷启动。
- 能量阈值 VAD 作为人声判定：已删除，仅保留能量用于波形和 dB 读数。
- 近场幅度门（按音量幅度判断远/近场再决定是否进预览）：已尝试并移除，仅靠幅度无法区分远近，且容易误挡用户自己说话。
- 停顿后重置实时预览窗口：已回滚，破坏自然口述体验。
- WebRTC VAD 前置粗筛：已搁置，当前性价比不足。
- 预览短分段拼接路线：历史上造成跳变和上下文断裂，不得直接复活。
- 截图双向翻译：降为 P3 / Backlog。
- 右侧横向滚动设置面板：已撤回，主窗口恢复 Classic Mac inspector 方向，只保留纵向滚动设置区。
- 聊天整理模式永久移除：已回滚，当前聊天模式和社交自动范围已恢复。

## 6. 核心用户旅程

### 6.1 第一次启动

目标：用户理解 TypeWhale 是什么，并完成最少必要配置。

流程：

1. 用户启动 TypeWhale。
2. App 创建状态栏入口和主窗口。
3. 主窗口显示麦克风、辅助功能、热键和模型状态。
4. 用户按提示授予麦克风和辅助功能权限。
5. 用户确认默认录音快捷键或重新录入。
6. 用户在任意输入框测试录音。

验收标准：

- 权限未开启时必须显示清楚的状态和恢复入口。
- 模型缺失时必须显示明确原因，不应静默失败。
- 未配置 DeepSeek 时，本地语音输入主链路仍然可用。
- 主窗口不能像营销页，应是紧凑工作台。

### 6.2 日常语音输入

目标：用户在当前应用中自然说话，最终文本可靠出现。

流程：

1. 用户把光标放在目标输入位置。
2. 用户按下录音快捷键。
3. TypeWhale 捕获目标应用和输入上下文。
4. 胶囊出现但不抢焦点。
5. 用户说话，胶囊显示状态、波形、电平和实时预览。
6. 用户松开快捷键或再次按快捷键结束。
7. App 对完整录音做 final ASR。
8. 可选执行智能整理或翻译。
9. App 恢复目标应用并粘贴最终文本。
10. 最近转录记录最终文本、模式、耗时、费用等信息。

验收标准：

- 录音开始响应应接近即时。
- 胶囊不能抢走目标输入框焦点。
- 目标应用短暂变化时，不得把结果粘贴到 TypeWhale 自身、桌面或错误应用。
- 发出 Command-V 前必须确认系统剪贴板能读回本次文本；若剪贴板已被其他应用改写，应取消自动粘贴并保护对方的新剪贴板内容。
- 粘贴失败时，最终文本必须保存在最近转录。
- final 粘贴不得使用实时预览文本。

### 6.3 长句与自然停顿

目标：用户可以自然思考、换气、停顿，不被系统误判为结束或重置。

验收标准：

- 自然停顿不能清空已显示预览。
- 已提交前缀应保持稳定。
- 长录音实时预览开销不能随总时长 O(n²) 增长。
- 到软时长后，应优先等 Silero 判定的停顿再分块，避免切词。
- 一直不停顿时，必须有硬上限兜底。

### 6.4 智能整理

目标：用户把口语变成更适合目标场景的文本。

流程：

1. 用户开启智能整理。
2. 用户选择手动模式，或启用自动模式。
3. final ASR 完成后，系统根据目标 App、窗口标题和口述内容选择整理策略。
4. 本地 Ollama 或 DeepSeek 返回整理结果。
5. App 粘贴整理结果，并在最近转录中保留原文与整理信息。

验收标准：

- 原始口述是待整理素材，不是模型指令。
- 原文涉及代答、咨询、建议、安抚、引导或话术时，输出仍是用户要发送的需求或表达本身，不生成最终对象回复。
- 智能整理不得擅自翻译。
- 开发需求模式必须保留语义、约束、风险和用户表达强度。
- 极致归纳不得删除安全、隐私、密钥、上传、提交、删除、覆盖等高风险红线。
- 自动模式的规则必须可理解、可配置、可回退。
- 本地 Ollama 不可用、DeepSeek 超时、失败、未配置 Key 或成本熔断时，应回退本地识别文本。

### 6.5 自动翻译

目标：用户明确需要跨语言输出时，翻译作为独立功能介入。

验收标准：

- 自动翻译开关与智能整理独立。
- 翻译方向明确，不能藏在智能整理模式里。
- 中译英要适合真实聊天和工作表达，保留语气和意图。
- `中译英·多表情聊天` 是用户可手动强制选择的翻译方向，适合轻松社交文本；社交窗口中常规中译英也可自动使用同一类聊天模板。
- 多表情聊天模式中，emoji 应贴近对应名词、动作或情绪词；普通短聊天保持克制，清单、枚举或多场景文本可以一项一个语义 emoji；不得把多个语义 emoji 集中堆到句尾。
- 严肃、正式、技术排查、争议、隐私、医疗、法律、财务或坏消息内容默认不加 emoji。
- 英译中要自然、清晰、不过度解释。
- 最近转录应同时保留原文、译文和费用信息。

### 6.6 截图、OCR 与截图翻译

目标：用户把屏幕内容快速变成可复制、可保存、可理解的信息。

流程：

1. 用户触发截图快捷键。
2. TypeWhale 打开非主窗口唤醒的截图覆盖层。
3. 用户拖拽普通选区，或悬停后点击选择窗口。
4. 用户可标注、撤销/前进、OCR、复制、保存、翻译或归档。
5. 英文截图翻译时，系统 OCR 行级识别、翻译为中文、遮盖原文并贴入译文。
6. 知识归档时，系统 OCR 选区内容，可选智能整理后写入 Obsidian 需求池，并保存同名截图附件。

验收标准：

- 进入截图模式不能唤醒主窗口。
- 普通拖拽框选与窗口点击选择语义必须区分。
- 按下并拖动表示普通框选；按下并松开才表示选择窗口。
- 自动翻译截图完成后，复制和保存的 PNG 必须包含译文层。
- OCR 空结果不应调用 DeepSeek。
- DeepSeek 失败时截图浮层不关闭，用户仍可复制、保存或取消。
- 录音中、识别中或整理中触发截图不应被入口直接拦截，也不应结束当前语音会话。
- 截图归档不应改写剪贴板；AI 整理失败但 OCR 成功时，应保存 OCR 原文并明确标记 warning。
- 截图附件应保存到当天归档目录下的 `附件/` 子文件夹，Markdown 使用相对路径引用。

### 6.7 闪念胶囊

目标：用户在不打断当前输入目标的情况下快速捕捉想法。

流程：

1. 用户触发闪念胶囊快捷键。
2. TypeWhale 打开带蓝紫内发光的录音胶囊。
3. 用户口述想法、产品判断、实现方向或待办。
4. App 做 final ASR，并按闪念胶囊独立整理模式处理。
5. App 自动保存 Markdown 到 Obsidian 需求池的“闪念胶囊/日期”目录，不自动粘贴到当前 App。

验收标准：

- 闪念胶囊有独立整理模式，不跟随主录音全局整理模式；默认是“即时归纳”。
- 支持即时归纳、开发需求、极致归纳、润色和原文，不支持自动模式。
- Markdown front matter 必须记录实际使用的整理模式，避免后台完成时被后续设置变化污染。
- 文件名继续保持 `YYMMDD-HHmm-主题-idea-pill.md`，同一天进入同一个日期子文件夹。
- 普通录音胶囊、健康绿环和状态高亮边框不受闪念内发光影响。

### 6.8 模型管理与 Pro ASR 实验支撑

目标：用户和开发者可以看见、下载、停止和复用 Pro ASR 候选模型，为热词和中英混合评测提供可控基础。

验收标准：

- 模型面板列出候选 ASR / VAD / 标点模型及能力说明、预计大小、目标子目录和下载状态。
- 下载目标固定在用户级 Application Support 目录，覆盖安装 App 不会清理已下载模型。
- 下载先进入 staging 目录，成功后再原子替换正式目录；半包不能被标记为可用模型。
- 下载进度由真实落盘字节和模型体积基准计算；覆盖安装后可接管仍在运行的 ModelScope 下载。
- 停止下载必须终止当前 App 发起的下载进程，并让模型回到可重新下载状态。
- Pro ASR 候选模型不因出现在模型面板就成为默认识别主路；必须先通过评测、provider 能力声明和实验开关。

### 6.9 OpenClaw 语音对话（实验功能）

目标：用户通过 TypeWhale 的本地语音输入能力，直接把口述内容发送给本机 OpenClaw，并在屏幕上看到小龙虾回复，不打断当前桌面工作流。

实验定位：

- OpenClaw 语音对话是 TypeWhale 的外部代理交互实验，不是普通输入粘贴主链路。
- 该能力验证“语音 -> 本地 ASR -> OpenClaw -> 屏幕回复”的产品价值。
- 实验期间必须保留清晰视觉标识：红色胶囊、小龙虾图标、OpenClaw 设置 Tab 和回复堆栈。
- 不得把 OpenClaw 回复自动写入当前输入框；用户需要明确区分“我在输入文字”和“我在和小龙虾对话”。

流程：

1. 用户在主窗口 OpenClaw Tab 查看或配置 Gateway、Agent、Session、CLI 路径。
2. 用户点击“检测连接”，确认本机 OpenClaw Gateway 可用。
3. 用户在 OpenClaw Tab 自己录入激活键后，触发该激活键启动 OpenClaw 语音模式；默认状态不占用任何系统功能键。
4. TypeWhale 显示红色录音胶囊，胶囊右上外侧有独立小龙虾标识，不能被胶囊遮挡。
5. 用户说话，TypeWhale 使用完整录音 final ASR 得到最终文本。
6. App 将最终文本发送给 OpenClaw CLI / Gateway。
7. OpenClaw 回复后，TypeWhale 在左上角展示红色小弹窗式回复堆栈，同时把“我 / OpenClaw”记录到最近转录。

验收标准：

- OpenClaw 激活键默认未设置；用户未录入前，不注册 OpenClaw 全局热键，也不占用 F6 或其它系统功能键。
- 用户设置 OpenClaw 激活键后，该键只进入 OpenClaw 语音模式，不触发普通 dictation、截图、翻译或闪念胶囊。
- OpenClaw 激活是独立开关语义：触发一次开始，再触发一次结束；松开按键不应走普通长按结束逻辑。
- OpenClaw 语音模式不自动粘贴到前台 App，不改写剪贴板。
- 红色录音胶囊必须和普通胶囊、闪念胶囊、健康绿环视觉上可区分。
- 左上角回复堆栈必须不抢焦点、点击穿透、不影响当前 App 输入。
- 回复堆栈最多展示 5 条；第 6 条到来时最旧回复向上移出，最新回复始终位于堆栈底部。
- Gateway 不可用、CLI 缺失、OpenClaw 超时或失败时，最近转录保留用户语音文本和错误说明，不吞掉内容。
- 实验功能必须在 PRD、开发日志、版本历史中明确标记，后续是否升级为正式能力需基于真实使用反馈决定。

### 6.10 本地 TTS 语音合成（实验功能）

目标：在本地部署开源 TTS 模型，把文字合成为接近正常人的语音，为后续“读出回复、朗读文本、语音反馈”等能力提供可验证的输出侧基础。

实验定位：

- 推荐方案是本地 sidecar 服务：TypeWhale 主 App 通过本机 HTTP / IPC adapter 调用 TTS 服务，不把 Python、PyTorch 或大型 TTS runtime 直接嵌入主进程。
- 模型管理器负责下载、校验、修复和删除完整的 MeloTTS 中文语音包；默认 DMG 不内置语音包。
- 本地自然声音固定采用 MeloTTS 中文音色，不再提供 Qwen3-TTS、CosyVoice2、音色克隆或角色语气选择。
- 该能力属于输出侧增强，不改变“语音输入 -> final ASR -> 可选整理 -> 粘贴”的主链路。

流程：

1. 用户在设置中开启本地 TTS 实验能力。
2. App 检测本机 TTS sidecar 是否已安装、运行、健康可用。
3. 用户可下载、停止、修复或删除 MeloTTS 中文语音包。
4. 用户输入一段测试文本或从未来支持的业务场景发起朗读。
5. App 将清理并分句后的文本发送给本地 sidecar；音量和语速由播放层控制。
6. sidecar 返回音频文件或本地音频流，App 播放或展示可用状态。

验收标准：

- Given TTS 未安装或 sidecar 未运行，When 用户打开设置，Then 主语音输入、OpenClaw 对话、截图和粘贴链路保持可用，并显示 TTS 不可用原因。
- Given sidecar 健康且模型可用，When 用户输入测试文本，Then 可生成并播放一段自然、清晰、接近正常人的语音。
- Given 模型下载中断，When 用户重新打开 App，Then 模型管理器能显示可恢复、可重试或可清理状态，不把半包标记为可用。
- Given sidecar 合成失败、超时或崩溃，When 用户触发朗读，Then App 不崩溃、不阻塞主录音，不吞掉原始文字，并给出可诊断错误。
- Given 进入商业发布准备，When 选择默认模型，Then 必须复核代码许可证、权重许可证、模型再分发权和使用限制。

出范围：

- 第一阶段不把大型 TTS 模型默认打进 App 包或公开 DMG。
- 第一阶段不把 Python / PyTorch runtime 嵌入 TypeWhale 主 App 进程。
- 第一阶段不默认开启 OpenClaw 回复自动朗读；OpenClaw 现有“不做 TTS 朗读”边界继续有效，除非后续单独批准。
- TTS 失败不得影响 ASR、VAD、智能整理、截图、粘贴或 OpenClaw 文本回复展示。

Ready 状态：Implementation。MeloTTS 热态短句实测约 `0.7~1.1s`，工作集约 `3~4GB`；OpenClaw 等待回复时预热，完全空闲 180 秒后释放。

#### Sherpa Native TTS 产品化候选

目标：在保留当前 Sherpa Python sidecar 可用体验的同时，验证一个不依赖 Python 的 Sherpa Native TTS 路径，提升桌面产品分发完整度。

验收：

- 用户机器不需要安装 Python、pip 或命令行依赖。
- OpenClaw 文本回复、消息弹窗、复制、链接、ASR、截图和粘贴不受 TTS 失败影响。
- 中英混读、技术词、数字和符号的朗读效果不明显退步。
- 速度接近当前 Sherpa 路径，内存明显低于 MeloTTS。
- 第三方代码、运行时和模型授权完成记录后才进入可分发默认路径。
- 在验证完成前，仅允许隔离测试 App 显式打包 runtime；正式版默认与设置 UI 不切换到 native 路径。

### 6.11 后台、睡眠唤醒与长期运行

目标：TypeWhale 可以像输入辅助工具一样长期运行。

验收标准：

- 关闭主窗口后，App 可继续状态栏后台运行。
- 系统 sleep 前应取消或保护录音状态。
- wake 后应有短保护期，避免立即重载模型或误触发热键。
- 后台不应持续高频轮询权限和热键。
- 覆盖安装或 App 重启后，模型下载、旧 staging 和孤儿下载进程要能恢复、接管或安全清理。
- 高内存安全网仅在空闲且超过动态预警阈值时触发：`min(20GB, max(2GB, 本机物理内存 * 25%))`。
- 释放 ASR/VAD 后必须立刻 warm reload，避免下一句冷启动。

## 7. 功能需求

### 7.1 全局快捷键与录音控制

优先级：P0

用户故事：

作为高频输入用户，我希望用一个全局快捷键在任何应用里开始和结束录音，以便不离开当前输入位置完成文字输入。

需求：

- 支持主快捷键和备用快捷键。
- 支持单击切换录音。
- 支持长按说话、松开结束。
- 支持截图、自动翻译和打开主窗口的独立快捷键。
- 支持闪念胶囊独立快捷键。
- 支持 OpenClaw 语音对话独立激活键，默认未设置，由用户在 OpenClaw Tab 内自行录入。
- 自动翻译和打开主窗口快捷键默认不设置，避免冲突。

验收标准：

- 快捷键录入后立即反映到 UI。
- 快捷键冲突或不可用时要给出可理解提示。
- 长按模式松开后必须结束录音，不依赖停顿自动完成。
- 停顿自动完成只适用于非长按模式。
- 录音入口切换遵循“我开、我关；我开、他开；先关我，再开他”：同一入口 key-down 不提前结束录音，不同入口可立即启动新录音并让旧任务后台完成。
- 录音键和截图键完全相同时，必须保留冲突保护，避免一次按键同时启动录音和截图。
- OpenClaw 激活键若读到未知或不可显示的异常 keyCode，应自动清空为未设置，避免误弹或不可理解的快捷键状态。

### 7.2 录音胶囊

优先级：P0/P1

用户故事：

作为正在口述的用户，我希望看到一个不打扰当前工作的录音胶囊，以便确认 TypeWhale 正在听我说话并理解方向。

需求：

- 胶囊不抢焦点。
- 显示录音状态、目标应用、模式、波形、dBFS 电平和实时文本。
- 自动整理模式下，胶囊顶部应显示上下文解析出的实际整理模式，而不是只显示“自动”；自动解析模式使用可识别强调色。
- 闪念胶囊使用独立的蓝紫内发光视觉，中心区域也应有淡紫覆盖，不只停在边框附近。
- 本地 Ollama 健康态可显示健康绿环；倒计时、内存高压等风险状态优先覆盖健康态。
- 空状态波形使用 1.2 已验证的 7 段柱状波形体验。
- 文字动效保持局部、稳定、可读。
- 实时预览过滤静音/噪音幻觉（中英文字幕腔短语黑名单，如「谢谢观看」「yeah」「the」），仅作用于预览，不影响 final 粘贴。
- 实时预览按块提交：滚出当前块的文本冻结进已提交前缀、不再重识别（稳定不跳变），仅最近一块的尾巴随重识别更新。

验收标准：

- 不能整段闪烁。
- 不能整段硬切导致用户丢失上下文。
- 长文本不能撑破胶囊布局。
- 实时预览为空时仍要有明确录音状态。

### 7.3 本地 ASR 与最终识别

优先级：P0

需求：

- 使用本地 SenseVoice / sherpa-onnx / ONNX Runtime。
- final ASR 输入来自完整录音文件。
- 实时预览与 final 识别架构分离。
- 模型和 runtime 缺失时要诊断清楚。
- ASR provider 必须声明能力，尤其是 hotwords / contextual biasing / language coverage；不支持热词的 provider 不能被静默当作热词主路。

验收标准：

- final 识别结果进入粘贴和最近转录。
- 实时预览和 final 文本不一致时，以 final 为准。
- 无人声时不粘贴空文本。
- ASR 失败时保留错误状态，不崩溃。

### 7.3.1 TypeWhale Pro 中英混合与热词 ASR 改造（规划中）

优先级：P0/P1

状态：

- 该能力是 Pro 分支规划与实验方向，尚不代表当前安装版已经实现。
- 详细决策和技术路线见 `docs/TYPEWHALE_PRO_ASR_STRATEGY.md`。

产品判断：

- TypeWhale Pro 的中英混合输入不能依赖不支持热词的单一中文 ASR。
- 如果 first-pass ASR 已经把英文实体识别错，后处理和整理模型往往没有足够证据恢复真实英文。
- 热词能力必须优先在声学侧、解码侧或并行 KWS / Word Spotter 侧路生效；后处理 canonicalizer 只能作为兜底。

目标链路：

```text
Audio Stream
-> VAD / 录音分段
-> Language & Hotword Router
   -> 中文 ASR 主路
   -> 英文 ASR / hotword ASR 侧路
   -> KWS / CTC-WS 热词声学检测侧路
   -> 不确定片段双路识别
-> Segment Merger
-> 本地整理模型
-> Safety Gate
-> Paste / Recent History
```

第一阶段验收：

- 建立真实中英混合评测集，覆盖 `Qwen3-ASR`、`sherpa-onnx`、`SpeechInputCoordinator`、`Obsidian` 等专有词。
- 证明至少一种本地热词声学侧路或支持 hotwords/contextual biasing 的 ASR 能在音频/解码阶段提升热词召回。
- 当前中文 ASR 保留为中文骨架和 fallback，不因实验 provider 失败而丢文本。
- 整理模型负责标点、空格和术语保真，不负责从完全错误的 ASR 文本里凭空猜英文实体。
- 离线评测 runner 缺少本地录音时必须输出 skipped / audio_missing，不得崩溃或伪造识别结果。

### 7.4 VAD、人声门控与自动结束

优先级：P0/P1

产品目标：

- 切换式录音中，用户说完单句话后无需再次按快捷键，持续停顿约 2 秒即可自动进入 final 识别。
- 自然思考停顿、阈值附近重新开口、慢 VAD 和快速连续录音不能造成提前截断或跨录音污染。
- 长按录音仍完全由松键结束；自动完成不能改变用户已经形成的长按操作预期。

需求：

- 人声判定唯一由 Silero 负责。
- Silero 在独立队列上录音中滚动检测，驱动停顿/人离自动结束，不与实时重识别抢队列。
- 停顿自动完成与胶囊实时预览必须独立配置；关闭实时预览后，VAD 和自动完成仍继续工作。
- 停顿自动完成只适用于非长按的切换式录音。
- 用户已说过话后，第一次达到停顿阈值的 `no_speech` 只进入待确认；第二次连续 `no_speech` 才允许结束。中间任何 `speech` 必须撤销候选。
- 单句话的目标用户体感为停止说话后约 2 秒完成。当前内部停顿基线为 `1.0s`，还需叠加最近 `0.7s` Silero 滚动窗口、约 `0.4s` 探测节奏和连续无人声二次确认；不得把内部常量误设为 2 秒导致实际接近 3 秒。
- 开场一直没有确认人声时，只有录音开始至少 8 秒后采集的 `no_speech`，且没有有效实时预览证据，才取消空录音；阈值前采集的旧结果不能触发取消。
- 每个实时 VAD 探测必须携带录音 task ID。旧录音异步回调不得修改新录音的人声状态、VAD 可用状态、界面或结束决策。
- VAD 忙时，等待探测的窗口进入小型有界 FIFO，不能用最新静音窗口覆盖包含短语音的中间窗口。
- 只要仍有更新音频等待 VAD，旧静音结果只能延期结束；必须先处理队列中的后续人声证据。
- 有界队列满时，安全停用本轮自动完成，保留手动停止、五分钟无输入安全网和六分钟硬上限；不能通过丢弃可能的人声证据继续冒险判断。
- 探测出错时停用自动结束，仅保留手动停止和硬上限。
- 自动结束日志必须至少区分 `pause`、`initial_silence`、手动结束、VAD 失败、队列压力降级和旧 task 回调，并记录 VAD 推理耗时与采样到决定的延迟。
非目标：

- 不用实时 ASR 是否吐字作为主要停顿计时器；实时文字仅可作为“已经存在有效语音”的安全证据。
- 不恢复能量阈值 VAD 作为人声真值；能量频带继续只用于波形和 dBFS 读数。
- 本阶段不增加“快速／标准／长口述”多档设置；先以约 2 秒单句话体验作为统一基线，通过可归因日志和真实使用反馈再判断是否需要分档。

验收标准：

- 开头静音不能产生成功感。
- 开始录音后等待 3 秒、5 秒或 7 秒再开口，录音不得提前停止，也不得丢失句首。
- 完全不说话时，应在约 8～9 秒取消空录音，不进入 final 识别、不粘贴文本。
- 用户说完一句话后持续安静，应以约 2 秒为目标自动结束；因设备和环境产生的合理探测浮动必须可从日志解释。
- 句中停顿约 1 秒后继续说，必须保留完整上下文，不能提前结束。
- 即将自动结束时重新开口，待结束候选必须撤销；后续短语音窗口不能被慢 VAD 队列覆盖或跳过。
- 长按录音停顿超过 3 秒时仍须继续录音，直到用户松开快捷键。
- 空录音自动取消后立即开始新录音，旧提示的延迟隐藏不得关闭新录音或新 final 识别胶囊。
- 快速连续开始两轮录音时，上一轮 VAD 回调不得污染或结束下一轮。
- VAD 失败或队列压力超限时，本轮不得自动结束；手动停止、无输入安全网和硬上限必须继续可用。
- 从按下到开始录音必须秒级响应，不允许再通过 Apple Voice Processing / 语音增强路径重建输入引擎。
- 不得仅凭音量幅度区分远/近场进预览（已验证不可行、易误挡用户自己说话）。

依赖与风险：

- 实际结束体感受输入设备、Silero 推理耗时、滚动窗口和系统负载影响，不能只用内部常量宣称用户体验已达标。
- 当前自动化覆盖纯策略、有界队列和协调器源码边界；真实麦克风下的约 2 秒体感、重开口和环境噪声仍需在安装版持续人工抽测。
- 当前实现与验证基线为 `1.9.37 (Build 639)`；核心实现提交为 `e69bb9f`，2 秒时长校准提交为 `6031254`。

### 7.5.1 应用范围与粘贴后自动发送

优先级：P1

需求：

- “智能 > 应用范围”和“常用 > 粘贴与发送 > 应用范围”打开同一个可调整大小的管理窗口，分别进入整理范围和自动发送分段。
- 应用目录支持最近使用、分类、搜索、多选、应用图标和仅看已配置；目录只在窗口打开时按需加载。
- 整理范围按 Bundle ID 设置应用默认模式，同时完整保留窗口标题、口述关键词、启用状态、规则顺序和 fallback 等高级规则。
- 自动发送使用独立总开关，默认关闭；每个应用可选关闭、回车或 `Command + 回车`。
- 自动发送只作用于普通、非翻译听写成功粘贴后的同一队列请求；翻译（包括失败回退）、闪念、OpenClaw、空文本、粘贴失败和目标切换不得发送按键。
- 文字必须先完成粘贴，随后才显示独立的 `2.0 秒后发送 · 取消` 浮层；倒计时只控制追加按键，不得阻塞粘贴队列、剪贴板恢复或下一次录音。
- 倒计时浮层与当前生产胶囊横向居中，优先显示在胶囊上方 10px；上方空间不足时显示在下方，无胶囊位置时回退到屏幕底部。用户在重启后的第一次倒计时中单击“取消”也必须立即生效。
- 用户点击“取消”或按 Esc 时，只取消追加的回车或 `Command + 回车`，已粘贴文字必须保留。浮层不得抢走当前应用焦点。
- 倒计时内切换应用、开始新录音、产生更新任务或停止程序时，旧动作必须取消且不得补发；到期前必须再次核对目标应用，并保证最多发送一次。
- 胶囊实时预览关闭时，自动发送浮层仍应正常显示；两者不得联动。自动发送总开关关闭时只粘贴，不显示浮层。
- 设置窗口内的编辑先保存在草稿中；取消不写设置，保存时分别写入整理范围与自动发送配置，两个分段不得联动覆盖。

验收标准：

- 窗口不超过当前屏幕可用区域，标题、分段和保存/取消始终可见；应用列表与详情可独立滚动。
- 总开关关闭时仍可编辑应用动作，但运行时只粘贴不发送。
- 未配置应用只执行原有粘贴；配置回车或 `Command + 回车` 后，按键只在粘贴成功且目标仍一致时发出。
- 打开并直接保存旧高级规则后，规则内容、顺序和匹配结果保持不变。
- 应用扫描、设置 UI 和图标加载不进入 ASR、实时缓存或胶囊链路。

### 7.8.3 OpenClaw 语音对话实验

优先级：P1 实验功能

用户故事：

作为产品负责人 / AI 协作用户，我希望自己设置一个 OpenClaw 激活键，直接用语音和 OpenClaw 对话，并在屏幕左上角看到小龙虾回复，以便在不离开当前工作上下文的情况下快速调度外部代理，同时不占用 Mac 系统功能键。

需求：

- 主窗口新增 OpenClaw Tab，集中配置 Gateway、Agent、Session、CLI 路径和连接检测。
- OpenClaw 激活键默认未设置，用户可在 OpenClaw Tab 或统一“快捷键”Tab 内自行录入或清空；两个入口共享同一个绑定。
- OpenClaw 录音胶囊使用红色视觉，并在胶囊右上外侧显示小龙虾标识；小龙虾不能被胶囊盖住。
- OpenClaw 激活键采用独立开关语义：触发一次开始，再触发一次结束，不复用普通长按松开结束语义。
- 录音完成后复用 TypeWhale final ASR，发送最终文本给 OpenClaw。
- OpenClaw 回复以红色左上角堆栈展示，样式接近系统消息推送但不抢焦点。
- 左上角回复堆栈以 OpenClaw 回复为主信息；用户原话可以显示，但必须弱化为上下文提示，不能把用户自己说的话误当成 OpenClaw 回复。
- 单条 OpenClaw 回复过长时，卡片内回复区域应限制最大高度并支持滚动，避免遮挡过多屏幕。
- 回复堆栈按时间自上而下排列，最多 5 条，最新回复始终在底部。
- 最近转录保存“我：原文 / OpenClaw：回复”，作为失败排查和历史追溯入口。

验收标准：

- Given 用户未设置 OpenClaw 激活键，When App 启动，Then OpenClaw Tab 显示“未设置”，并且不注册 F6 或其它默认 OpenClaw 热键。
- Given 用户进入“快捷键”Tab，When 查看快捷键列表，Then OpenClaw 激活键和主快捷键、截图、自动翻译、唤起主页等入口一起出现，并使用同一套录入/清空交互。
- Given 用户在 OpenClaw Tab 录入了一个激活键且 Gateway 可用，When 用户触发一次开始、再次触发结束，Then 红色胶囊显示 OpenClaw 模式，最终回复出现在左上角堆栈底部，并进入最近转录。
- Given 已有 5 条 OpenClaw 回复可见，When 第 6 条回复到来，Then 最旧一条移出，最新一条保持在堆栈底部。
- Given 用户说出一句话且 OpenClaw 返回回复，When 左上角堆栈展示，Then 用户原话以弱化样式作为“我说”上下文出现，OpenClaw 回复以更高权重作为主内容出现。
- Given OpenClaw 返回长回复，When 回复超过卡片最大高度，Then 回复区域可在卡片内滚动，不把整张通知撑到遮挡主要工作区。
- Given 用户正在任意 App 输入，When OpenClaw 回复弹出，Then 当前 App 不失焦；通知区域可接收滚轮用于长回复滚动，但不得激活 TypeWhale 或把焦点从当前 App 抢走。
- Given OpenClaw CLI 不存在或 Gateway 失败，When 用户完成 OpenClaw 录音，Then 不自动粘贴，不清空识别文本，最近转录记录失败说明。
- Given 本地存储了未知 OpenClaw keyCode，When App 启动，Then 自动清空为未设置，不回退 F6。

出范围：

- 不做 OpenClaw TTS 朗读。
- 不自动把 OpenClaw 回复粘贴到前台应用。
- 不把 OpenClaw Session 管理升级为完整多会话 UI。
- 不把 TypeWhale 改造成 OpenClaw 内部插件。

- 支持截图 OCR 知识归档，归档可使用极致归纳、开发需求、润色或原文整理模式。

- 归档同时保存选区截图附件到当天目录的 `附件/` 子文件夹，并在 Markdown 中用相对路径引用。
- 归档过程显示页面内状态和顶部 toast；后一张截图归档不得取消前一张已开始的归档。

验收标准：

- 标注、撤销、复制、保存、取消功能不回退。
- 新增前进按钮后，窄屏覆盖层下工具栏不能溢出屏幕。
- OCR 识别成功并复制到剪贴板后，顶部提示标题应为“已复制”。
- 翻译失败不关闭截图浮层。
- 译文层不会越出选区。
- 保存和复制输出一致。
- 归档不改动剪贴板；AI 整理失败但 OCR 成功时应保存 OCR 原文并标记 warning。
- 语音输入中触发截图仍可进入覆盖层，且录音继续保持。

### 7.10 模型管理与下载

优先级：P1/P2

需求：

- 主窗口提供模型管理入口；当前受管 ASR 下载项只保留 Fun-ASR Nano 与 FSMN-VAD 分段依赖。
- 最终识别只保留 SenseVoice int8、Parakeet TDT 0.6B v2、Fun-ASR Nano、Qwen3-ASR 0.6B MLX 8-bit 与 Qwen3-ASR 1.7B MLX 8-bit。
- Paraformer Contextual、Paraformer zh、SeACo Paraformer、Whisper Small MLX、Qwen3 Sherpa 与 Zipformer 不适合当前 TypeWhale 的准确性、速度、资源效率和产品化目标，不再提供。
- 每个模型展示能力、预计大小、目标子目录、下载状态和操作按钮。
- 下载目标固定在用户级 Application Support 目录，覆盖安装不清理。
- 下载过程使用 staging 目录和原子提交；失败或停止后的半包不能被标记为可用。
- 下载中显示真实进度，按钮可停止；停止使用 TERM 后 KILL 兜底。
- 覆盖安装或重启后，应根据 ModelScope 进程和 staging 目录接管、恢复、失败或清理下载状态。
- 本地大模型 Qwen3 / Qwen3.6 链接作为 Ollama 下载入口展示，不进入 ASR 模型目录。

验收标准：

- 模型列表行列对齐稳定，短模型名和长模型名从同一视觉列开始。
- 未下载是中性状态，失败才使用错误状态。
- App 启动和主窗口创建不能因扫描下载进程而卡住。
- 0B staging 和孤儿下载进程能被安全治理。
- Pro ASR 候选模型不会绕过评测和能力声明直接进入默认主识别链路。

### 7.11 本地 TTS 语音合成实验

优先级：P2 实验功能 / Spike First

用户故事：

作为希望 TypeWhale 能“说出来”的用户，我希望先在本地验证一个自然、接近正常人的开源 TTS 模型，以便未来可以安全地朗读文本或 AI 回复，而不把语音和文字上传到云端。

需求：

- TypeWhale 主 App 只通过本地 sidecar adapter 调用 TTS，不直接承载大型模型 runtime。
- sidecar 提供预热、合成、关闭、失败原因和输出音频路径。
- TTS 候选模型直接列入现有“状态 > 模型”界面，与 ASR / VAD / 标点模型统一管理；不单独开一个重复的模型下载页。
- 模型管理器负责完整 MeloTTS 语音包的下载、校验、停止、恢复、修复、删除和状态展示；下载目录仍使用用户级 Application Support。
- 完整语音包包含固定 Python 运行时、MeloTTS 中文模型、多语言 BERT 和最小文本资源；运行时禁止联网补依赖或执行 `pip install`。
- MeloTTS 使用固定中文音色；保留音量、语速、播放内容和打断策略，不提供模型、音色或角色选择。
- OpenClaw 等待回复时预热；活动结束后保温 180 秒，仅在合成与播放完全空闲时释放。
- TTS 是输出侧增强，不参与 final ASR、不参与自动粘贴、不改变 OpenClaw 文本回复展示。

验收标准：

- Given TTS sidecar 未安装，When App 启动或主窗口打开，Then TTS 状态显示不可用，但主输入链路无变化。
- Given sidecar 已运行但模型缺失，When 用户点击测试合成，Then UI 提示需要安装模型，不崩溃、不长时间卡住。
- Given sidecar 与模型均可用，When 用户输入中文测试句，Then App 能播放自然可懂的本地合成语音。
- Given 合成文本为空、过长或包含 Markdown/链接，When 用户触发合成，Then adapter 明确处理边界，不把原始异常冒泡成崩溃。
- Given sidecar 在合成中退出，When App 收到失败，Then 用户可看到失败状态，日志可定位 sidecar、模型、超时或音频播放层。

### 7.12 屏幕录制设置（未来需求）

优先级：P3 / Backlog

用户故事：

作为需要把操作过程、问题复现或产品反馈录下来的人，我希望 TypeWhale 未来能提供一套安静、可控、可信任的录屏设置，以便在不离开当前工作流的情况下快速录制屏幕、系统声音和必要的操作提示。

需求：

- 参考专业录屏工具的设置结构，录制前可配置麦克风、清晰度、帧率、格式、摄像头、录屏时长、倒计时、系统声音、鼠标点击、光标和按键显示。
- 默认配置应偏向低打扰、稳定和隐私：不默认录摄像头，不默认显示按键；系统声音、鼠标点击和光标显示必须由用户明确选择。
- 录屏入口必须与现有语音输入和截图链路隔离，不能抢占录音快捷键、截图快捷键或主窗口生命周期。
- 录屏设置 UI 需要有录制前确认态，明确展示即将录制的屏幕范围、音频来源、输出格式和保存位置。
- 录制输出应支持直接保存到用户配置目录，后续可再评估复制到剪贴板、压缩、转写、翻译或生成反馈包。

验收标准：

- 用户开始录制前能看清并修改麦克风、系统声音、摄像头、帧率、清晰度、格式、倒计时和保存位置。
- 未获得屏幕录制、麦克风或系统音频权限时，界面必须解释缺失权限和恢复路径，不静默失败。
- 录制过程中不能影响 TypeWhale 语音输入主链路的热加载、快捷键响应和粘贴目标保活。
- 开始、暂停、继续、停止、保存失败和取消都必须有可观察状态，不丢失已录片段。
- 敏感输入场景下默认不显示按键内容；如提供按键显示，必须有明显开关和隐私提示。
- UI / 动效实现前必须走设计复核，验证倒计时、录制中状态、鼠标/按键提示不会遮挡用户主要操作内容。

## 8. 非功能需求

### 8.1 性能

- 快捷键到录音开始应接近即时。
- 胶囊首个可见反馈优先于完美识别。
- 实时预览不能因长录音整段重识别造成 O(n²) 卡顿。
- 后台空闲不能持续高 CPU 或高频唤醒。

### 8.2 稳定性

- 录音、final ASR、智能整理、翻译、粘贴是可隔离阶段。
- 任一增强阶段失败，不应导致本地识别文本丢失。
- 后台语音任务、截图归档任务和模型下载任务互不抢占，不应因为新会话开始就丢弃旧任务结果。
- 睡眠、唤醒、权限变化和模型 reload 不能破坏下一次录音。

### 8.3 隐私与安全

- 音频默认本地处理。
- 剪贴板只为粘贴临时替换，并尽量恢复。
- 不添加隐式遥测。
- API Key 应安全保存。
- 剪贴板就绪闸门必须保护用户在粘贴前被其他 App 写入的新剪贴板内容。
- 截图和 OCR 内容调用远程翻译时必须属于用户主动触发。
- 截图归档保存的 Markdown 和附件属于本地需求池资料，不应自动上传。
- 未来录屏能力涉及屏幕像素、系统声音、摄像头、麦克风和按键显示，必须默认关闭高敏感来源，并在录制前给用户明确确认。

### 8.4 分发与授权

- 公开分发前必须完成 Developer ID 签名、公证和 Gatekeeper 验证。
- 模型授权必须复核，尤其是 SenseVoice / FunASR 商业再分发。
- TTS 模型授权必须单独复核代码许可证、权重许可证、商用条款和再分发限制；未确认前不得作为默认模型打包或推荐给商业用户。
- 第三方组件声明必须同步。
- README 必须区分本地安装版和可分享 DMG。
- GitHub 可分发 DMG 可以内置基础 ASR/VAD 模型以保证本地语音输入可用，但不得打入 Ollama / LLM 大语言模型，也不得默认打入大型 TTS 模型。

### 8.5 可诊断性

- 权限、模型、热键、ASR、VAD、粘贴目标、DeepSeek 调用和成本应可诊断。
- 用户反馈“卡顿、发热、粘贴失败、预览不动”时，日志应能区分是哪一层失败。
- 用户反馈“下载中卡住、覆盖安装后模型状态不对、截图翻译很慢、归档没保存”时，日志应能区分进程、staging、OCR、翻译和文件写入状态。
- 诊断日志按「每天一个文件夹、每个 build 一个文件」归档（`~/Library/Logs/TypeWhale/<日期>/<版本>-<build>.log`），`latest.log` 软链指向当前 build，并保留近 14 天；Swift 与原生崩溃日志器写同一文件。
- 录音链路保留关键计时埋点（开始耗时、人声检测耗时、停录等待、粘贴目标解析），便于定位“慢/不输出”是哪一层。
- 诊断增强不能反过来造成后台高频工作。

## 10. 当前风险

### 10.1 胶囊与实时预览仍是高风险体验区

实时预览承担用户信心锚点，但当前仍依赖非流式 ASR、分块提交、Silero 停顿和视觉缓存配合。任何改动都容易造成跳变、闪烁、延迟或上下文断裂。

风险控制：

- 对比 1.2 已验证体验。
- 保持 final ASR 与 preview 独立。
- UI/交互动效改动必须做设计复核和安装版验证。

### 10.2 粘贴目标正确性是输入工具生死线

用户使用 TypeWhale 的结果最终要回到当前工作流。粘错目标比识别失败更严重。

风险控制：

- 保留录音开始目标。
- 忽略瞬时不可粘贴前台。
- 粘贴前确认剪贴板已准备好本次文本。
- 剪贴板被其他 App 抢先更新时取消自动粘贴。
- 粘贴失败保留最近转录。
- 继续补目标应用兼容性矩阵。

### 10.3 智能整理容易越权成问答代理

TypeWhale 的智能层越强，越容易把用户口述中的“回复、建议、引导、话术”误理解为让模型直接替最终对象回答。这会把输入工具变成不受控的问答代理，破坏用户意图保真。

风险控制：

- 全局安全边界统一维护在本地和在线引擎共用的提示词层。
- 开发需求、聊天、润色、即时归纳和极致归纳都继承“只整理不代答”边界。
- 用真实咨询/代答样本做回归检查。

### 10.4 模型和第三方授权影响商业化

当前源码开源不等于模型可商业分发。公测、付费、朋友分发和正式商业化前必须重新审查模型、runtime 和第三方条款。

风险控制：

- 不把模型文件提交到仓库。
- 分发包前复核第三方声明。
- 明确本地安装版和公开 DMG 的差异。

### 10.5 后台性能问题容易被外部 App 混淆

TypeWhale 常驻状态栏，用户遇到系统卡顿时容易怀疑它。必须用诊断证明自己是否在主链路外保持安静。

风险控制：

- 保持后台 timer 降频。
- 增强但不过度增加诊断日志。
- 必要时采样证明主线程、ONNX worker 和 WindowServer 关系。

### 10.6 模型下载与 Pro ASR 实验不能污染主链路

模型面板和 Pro ASR 热词计划会引入更多模型、进程和下载状态。如果没有清晰边界，容易造成启动卡顿、半包误用、默认识别链路被实验模型污染。

风险控制：

- 下载检查必须后台执行，不能阻塞主窗口创建。
- staging、进程和正式目录必须三方一致后才标为可用。
- ASR provider 能力元数据和评测集是接入主路前置条件。

### 10.7 OpenClaw 实验不能造成误弹、误贴或焦点打断

OpenClaw 语音对话会引入外部 CLI、Gateway、Agent Session 和屏幕回复堆栈。如果它和普通语音输入混在一起，用户可能误以为自己在输入文字，结果却在和 OpenClaw 对话，或被回复弹窗打断当前工作。

风险控制：

- OpenClaw 必须使用独立快捷键、独立胶囊视觉、独立设置 Tab 和独立回复堆栈。
- OpenClaw 成功和失败路径都不得自动粘贴，不得改写剪贴板。
- 回复堆栈必须是非激活、点击穿透窗口。
- 快捷键异常存储必须自动清空为未设置，避免不可读快捷键导致误触；不得回退到 F6 或其它默认键。
- OpenClaw Gateway 检测失败只能影响 OpenClaw Tab 状态，不能影响普通录音、截图、翻译、闪念胶囊或模型热加载。

## 11. 路线图

### P0：输入主链路绝对稳定

- 继续验证长录音、自然停顿和远场噪声。
- 修正任何粘贴错目标、文本丢失、胶囊停字、主窗口误唤醒问题。

## 13. PRD 维护规则

- 新增明显产品能力、重大回滚、发布封版或商业化边界变化时，必须更新本文。
- 如果只是实现细节、日志、测试命令或修复过程，优先更新 `docs/开发日志.md`。
- 如果是架构不可逆决策，更新 `docs/ARCHITECTURE.md`，并在 `docs/开发日志.md` 记录日期、原因、影响和验证。
- 如果是 UI、交互或动效体验规则，更新 `DESIGN.md`。
- 实验必须明确标记为实验、搁置或已回滚，不能写成当前能力。
- PRD 中的验收标准必须是可观察行为，不能只写“更好、更稳、更丝滑”。
